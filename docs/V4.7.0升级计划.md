# AitionOWS V4.7.0 升级计划(前台内容呈现:改文件名失效 + 摘要/关键词 + 列表作者 + 详情页宽度)

> 分支 main(基于 v4.6.7) · 零迁移 · 预计 1.5 天
> 范围:① 后台「改文件名」无效(缺陷) ② 文章详情页的摘要/关键词排版(新增展示) ③ 文章列表卡片加作者 ④ 详情页宽度太窄
> 说明:本文档只做分析与方案,确认后再动代码

## 一、问题确认(证据)

### 1. 「修改文件名」无效 —— 写错了字段,而且是死字段

链路(`src/app/[locale]/(admin)/admin/(panel)/media/page.tsx:117` → API → 服务层):

```
renameFile():  promptDialog({ title: "修改文件名(展示名)", defaultValue: row.filename })
               apiPost("/api/admin/media", { id, alt: name.trim() })      ← 写的是 alt
API:           postSchema = z.object({ id, alt: z.string().max(200) })
               updateMediaAlt(id, alt)                                   ← 只更新 alt
列表渲染:       {m.filename}                                              ← 显示的是 filename
前台消费:       全站 <img alt> 都用 content.title / t.title,没有人读 MediaAsset.alt
```

**结论**:弹窗声称"改文件名"、预填 `filename`,但保存进 `alt`;而列表与素材选择器显示的是 `filename`,`alt` 在前台也没有任何消费点 → 无论保存成功与否,**界面上永远看不到变化**,所以表现为"无效"。这不是偶发故障,是字段与文案不一致的设计缺陷。

### 2. 摘要 / 关键词:字段都有,详情页一个都没渲染

- 数据结构齐备:`ContentTranslation.summary`(摘要)、`ContentTranslation.seoKeywords`(SEO 关键词,编辑器标注"逗号分隔");详情服务 `getPublishedBySlug` 也已返回两者(`src/server/content/index.ts:637` 附近)
- 详情页实测(`https://www.aition.xin/zh-CN/article/post-mtyhb49w`):页面内**无摘要块、无关键词**;`generateMetadata` 里 `keywords` 已写入 meta —— 即**关键词目前只给搜索引擎看,访客看不到**

### 3. 文章列表卡片没有作者

`ContentCard`(`src/components/site/content-card.tsx`)只渲染:封面 / 标题 / 摘要 / 日期 / 阅读 / 点赞,元信息行里没有作者。数据侧也缺:

| 环节 | 现状 |
|---|---|
| 列表查询 `listPublishedByCategory` 的 `select` | **未取 authorName**(`src/server/content/index.ts:550` 附近) |
| 卡片整形 `shapeCard` | 输入/输出都**未映射 authorName** |
| `ContentCard` 组件 | 未渲染作者 |
| 首页 `listLatestPublished` | 用 `include` 取全字段(authorName 在手),但同样被 shapeCard 丢掉 |
| 横向条目 `layout-presets.tsx` | 与 ContentCard 数据同构,需同步 |

注:详情页已有作者(`article/[slug]/page.tsx:129`,带 UserRound 图标),所以只是列表侧缺。

### 4. 详情页太窄

实测(`1440px` 视口,生产):

| 项 | 实测值 |
|---|---|
| `<main>` 类名 | `container max-w-3xl py-10` |
| 计算后 max-width | **720px**(站点根字号 15px,`48rem × 15 = 720`) |
| 正文 `.rich-content` 宽度 | **690px** |
| 正文字号 / 行高 | **13.125px**(`text-sm`,0.875rem)/ 21.3px |

两处不合理:① 1440 视口下左右各空 360px,大屏更空;② **站内不一致** —— 商品详情页是 `max-w-5xl`(1200px),同为主体的内容页却是 720px;③ 正文 13.1px 对长文偏小(720px 列宽下每行本就偏长,字号再小更吃力)。

## 二、修改方案

### 1. 修复「改文件名」(推荐方案 A)

**A(推荐):改名就改 `filename`**
- 新增服务层 `renameMediaAsset(id, filename)`(更新 `filename` 字段),API 增加动作分支 `{ action: "renameAsset", id, filename }`,`renameFile()` 改调它
- **物理文件与 `path` 不动**(uploads/ 下真实文件名不变,仅改展示名/SEO 名) → 零迁移、零文件风险;列表、素材选择器、后台所有显示名同步变化
- 校验:去首尾空格、长度 ≤ 200、非空;同名允许(不唯一约束),但**保留扩展名提示**(不强制)
- 顺带把 `alt` 从改名弹窗里摘出来:另立入口「图片说明(alt,SEO 用)」——目前它是死字段,建议同批做个能看见的出口(列表悬浮显示 + 素材选择器显示),或者本轮先只保留写入、不展示(由你定)

**B:只把文案改成"图片说明(alt)"** —— 保存后列表第二行显示 alt。能立刻"看得见变化",但不是用户想要的"改文件名"。

**C:A + B 合并**:同弹窗两个字段(展示名 / 图片说明)。字段清晰但弹窗变重。

### 2. 摘要与关键词的排版建议

**摘要 → 做成"导语块",放封面之后、正文之前**(推荐)

```
面包屑
H1 标题
作者 · 日期 · 阅读
────── 封面图 ──────
┃ 摘要文本(左侧 3px 品牌色竖线 + 稍大字号 + 弱化底色)
正文…
```

- 位置理由:这是传统媒体的"导语/编者按"位;封面是视觉钩子,摘要承接"这篇讲什么",正文紧跟。放标题之前会打断"标题→作者→正文"的常规动线
- 样式建议:左侧 3px 品牌色竖线(`border-l-4 border-primary/70`)+ `pl-4` + 字号比正文略大(约 15~16px)+ 颜色介于正文与次要文字之间;不加圆角边框,避免与正文里的"引用块"撞样式
- 细节规则:**摘要为空时整块不渲染**;摘要比正文短、但若与正文首段重复(常见的"摘要=首段"写法),建议**在后台编辑页给提示**而非自动过滤

**关键词 → 页面末尾的标签组**(推荐),放互动条之前

- 形态:`关键词:` 小标签 + 若干 chip(细边框、圆角、hover 变品牌色),解析时同时兼容中英文逗号(`,` / `，`)并去空白、去重、限个数(建议最多 12 个)
- 位置理由:关键词是元信息,放开头打断阅读;放末尾承接"读完→想找同类"的动线
- **注意**:站点目前**没有搜索页**(site 路由里无 /search)→ chip 不做跳转,纯展示;若你想让它可点,需要先做站内搜索(另立小项)
- 增强(建议同批做,零界面成本):`ArticleJsonLd` 增加 `keywords` 字段、并把摘要作为 `description` 的首选(现在是 `seoDesc || summary`,可改为 `summary || seoDesc`,因为摘要更完整)

### 3. 文章列表卡片加作者

- 数据链三处补齐:列表查询 `select` 加 `authorName: true`;`shapeCard` 输入/输出加 `authorName`;`ContentCard` 元信息行加作者
- 卡片样式:在日期前插入 `作者名`(带 `UserRound` 小图标,与详情页一致),字号沿用 `text-xs text-muted-foreground`;**作者名为空时整段不渲染**(不显示占位符)
- 同步范围:`c/[slug]` 栏目页(3 处调用)、首页楼层、`layout-presets.tsx` 横向条目;顺带核对"相关文章/最新内容"等其它卡片入口
- 取舍提示:卡片底部已有"日期 / 阅读 / 点赞"三项,再加作者会偏挤 —— 建议作者放在**标题下方、摘要上方**作一行小字(若你更想放底部也行,方案里我按底部一行排,视觉最省空间)

### 4. 详情页宽度(推荐方案 A)

**A(推荐):正文列放宽 + 媒体出血 + 字号跟进**
- 正文列:`max-w-3xl`(720px) → **`max-w-4xl`(840px)**,即正文约 810px
- 媒体出血:封面、正文内嵌图片/视频、表格用负 margin 突破正文列到约 **1080px**(`max-w-5xl` 宽度),形成"正文窄、媒体宽"的专业杂志版式;**移动端不出血**(负 margin 仅在 `md:` 以上生效)
- 字号跟进:正文 13.125px → **15px**(1rem)、行高 1.75 —— 列宽变大后必须同步放大字号,否则每行字符数过多反而更难读
- 移动端:窄屏下 `container` 本就占满宽度,以上改动**对手机无影响**

**B:整页通栏到 1080~1200px**(与商品详情页 `max-w-5xl` 对齐)
- 视觉冲击最强、站内最一致;但正文每行字符数会明显偏多,若同时把字号提到 15~16px 才站得住

**C:只加宽封面/媒体,正文列不动**
- 版面最"专业",但用户"页面还是窄"的观感不会消除

三方案都零迁移。若你只想最小改动,选 B 一行类名即可;想一次到位,选 A。

## 三、验证要点

1. **改名**:改完后列表卡片、素材选择器、后台所有显示名立即变化;物理文件仍可正常访问(URL 不变);重复名不报错;清空名被拒
2. **摘要**:有摘要 → 显示导语块且样式与正文区分;无摘要 → 整块不渲染,不留空白
3. **关键词**:中英文逗号混写都能正确切分;含空格/重复项被清洗;为空不渲染;chip 无点击行为(当前无搜索页)
4. **列表作者**:栏目页三种布局(网格/杂志/商品)、首页楼层、横向条目均显示作者;作者为空时不显示占位
5. **详情页宽度**:1440 与 1920 视口下正文宽度符合预期;媒体出血在窄屏不生效(375px 视口不出现横向滚动条);深浅两种系统外观正常
6. **回归**:文章详情页的 JSON-LD(用 schema 校验)、OG 标签、评论/收藏/互动条、附挂表单不受影响
7. 门禁:`tsc --noEmit`、`lint`、`vitest run`(现有 233 用例)、`next build`;补断言锁行为(摘要/关键词渲染、authorName 透传、关键词切分函数)
