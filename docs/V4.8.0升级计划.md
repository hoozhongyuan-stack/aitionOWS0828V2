# V4.8.0 升级计划 —— 拟真互动数据(阅读量 / 点赞量 / 转发量)

> 状态:**已开发完成**(2026-09-20),与 V4.8.1「内容置顶」合并发布为 **V4.8.0**
> 默认关闭(生产零影响);置顶部分见 [V4.8.1升级计划.md](./V4.8.1升级计划.md)

## 1. 需求还原

| 用户原话 | 拆解为工程约束 |
|---|---|
| 虚拟数据:阅读量、点赞量、转发量 | 三个计数都要有拟真层 |
| (2026-09-20 追加)收藏数据也需要考虑进去 | **收藏量同样纳入拟真**:第四项计数,由阅读按收藏率派生,真实收藏 1:1 叠加 |
| 发布一段时间内,按一定规则增长,但是随机的 | **自然增长曲线**:随时间累积,规则确定但逐篇/逐日带随机 |
| 一个真实的阅读,会乘于一个系数随机增加 | **真实放大**:每次真实阅读 × 随机系数(不是固定倍数) |
| 但又不是立马增加,而是慢慢增加 | **延迟释放**:放大量分 5 天释放,今天只出约 42% |
| 整体来说,数据是拟真的 | **拟真不变量**:只增不减、刷新不变、篇间量级不同、比例合理、无整数突变 |

## 2. 设计总则(为什么这样做)

1. **不落库、算出来**(读时计算):本项目没有定时任务(无 cron / 无 worker),如果靠定时器累加计数,一旦服务停机就断档、时间漂移无法回补。改为**确定性伪随机**(种子 = 内容 id + 日期 + 全局盐)按当前时刻直接算出展示值:停机再久也能"补"出这段曲线的产物,且天然幂等。
2. **真实与拟真分离**:`Content.viewCount / likeCount / shareCount` 仍是**真实计数**,任何人不可改(沿用既有铁律「后台不提供改写真实互动数据的接口」)。拟真值只在**展示层**合成,后台列表两列并排展示,任何时候可核对。
3. **一处计算、多处复用**:合成逻辑收敛到 `src/server/stats/`,前台所有出口(详情页、列表卡片、首页楼层、接口回包)同源,不会出现"列表 128 / 详情 130"的自相矛盾。
4. **默认关闭**:`stats.enabled` 默认 `false`,生产升级后行为与现在**逐字节一致**;由后台一键开启。

## 3. 算法

### 3.1 自然增长(organic)

每篇内容的"人气基数" P:

```
seed  = hash32(seedSalt, contentId, "organic")
z     = N(0,1)            // 由 seed 驱动的确定性正态抽样(mulberry32 + Box-Muller)
P     = baseViews × scale × exp(spread × clamp(z, -2.2, +2.2))
      // CUSTOM 模式直接用管理员填的 statsBase 作为 P
```

日权重(幂律衰减 + 星期因子 + 逐日抖动):

```
w(d)      = (d + 1) ^ (-decay) × weekday(d) × jitter(contentId, d, salt)
weekday   = [1.06, 1.08, 1.07, 1.05, 1.00, 0.83, 0.91]   // 周一…周日,均值恰为 1
jitter    ~ U(0.72, 1.28)                                  // 均值 1,逐日不同
norm      = Σ_{d=0..29} (d+1)^(-decay)                     // 与 baseViews 口径对齐:30 天累计≈P
```

累计展示阅读(当天按已过时长平滑释放,避免 00:00 跳变):

```
elapsedFraction(day) = smoothstep(当天已过毫秒 / 86400000)
views(now) = P × [ Σ_{d<今天} w(d) + w(今天) × elapsedFraction ] / norm
```

效果:一篇中位数文章发布后第 1 小时约 3 次阅读、第 1 天约 71、第 1 周约 200、第 30 天约 300(P=300 时),半年后约 430 —— 长尾不断,但永不陡增。

### 3.2 真实阅读放大 + 延迟释放(amplify)

每日真实阅读明细来自新表 `ContentDailyView`(由 `/api/interaction/view` 顺带写入)。

```
release = [0.42, 0.24, 0.16, 0.11, 0.07]        // 第 0/1/2/3/4 天释放比例,合计 1
K(day)  = amplify × jitterAmp(contentId, day)   // jitterAmp ~ U(0.55, 1.75) —— 「随机系数」
amplified(now) = Σ_天数 Σ_{i=0..4} realViews(day) × K(day) × release[i] × elapsedFraction(day + i)
```

效果:今天有 1 次真实阅读(默认 amplify=12):

| 时间 | 本次真实阅读贡献的展示阅读 |
|---|---|
| 当天 | +5(12×0.42) |
| 次日 | +8(累计,再 +3) |
| 第 3 天 | +10 |
| 第 5 天 | +12(释放完毕) |

即**不是立刻跳 +12,而是分 5 天慢慢长出来**,且每天系数独立随机。

### 3.3 点赞、转发与收藏

```
baseLikes     = 展示阅读 × likeRate     × jitterLike(contentId)      // jitter ∈ U(0.80, 1.25)
baseShares    = baseLikes × shareRate   × jitterShare(contentId)
baseFavorites = 展示阅读 × favoriteRate × jitterFavorite(contentId)
display       = base + 真实值(1:1 叠加)
```

真实点赞/转发/收藏 1:1 计入(保证前台点一下 +1,交互手感不变),拟真部分承担"量级"。
硬约束:`点赞 ≤ 阅读`、`转发 ≤ 点赞`、`收藏 ≤ 阅读`、全部非负整数。
收藏与点赞**不设序关系**:干货型内容的收藏常高于点赞,由 `favoriteRate` 决定谁多谁少(默认收藏率 1% 低于点赞率 2.2%)。

### 3.4 参数(后台可调,Setting group=`stats`)

| 键 | 含义 | 默认 | 范围 |
|---|---|---|---|
| `enabled` | 总开关 | **false** | — |
| `scale` | 全局强度倍数 | 1 | 0.1–10 |
| `baseViews` | 篇均基数(30 天累计阅读中位数) | 300 | 10–100000 |
| `spread` | 篇间差异 σ(越大越"几家欢乐几家愁") | 0.8 | 0–1.5 |
| `decay` | 冷却速度(越大冷得越快) | 0.95 | 0.5–1.5 |
| `amplify` | 真实阅读放大系数中位数 | 12 | 1–100 |
| `likeRate` | 点赞率(占阅读) | 0.022 | 0–0.2 |
| `shareRate` | 转发率(占点赞) | 0.22 | 0–1 |
| `favoriteRate` | 收藏率(占阅读) | 0.01 | 0–0.5 |
| `seedSalt` | 全局种子盐(换值 = 全站重掷曲线) | `"v1"` | 字符串 |

### 3.5 单篇覆盖

| 字段 | 含义 |
|---|---|
| `Content.statsMode` | `AUTO`(跟随全局,默认)/ `OFF`(此篇不模拟,只显示真实值)/ `CUSTOM`(用自定义基数) |
| `Content.statsBase` | `CUSTOM` 时的 30 天累计阅读基数 |
| `Content.statsSalt` | 单篇盐:「重新随机」按钮写入新值 → 该篇曲线重掷(量级不变、日内分布与篇间随机项变化) |

## 4. 数据模型

```prisma
model Content {
  // …既有字段不动…
  viewCount    Int @default(0)   // 真实计数(只读)
  statsMode    String  @default("AUTO")  // V4.8.0 拟真:AUTO/OFF/CUSTOM
  statsBase    Int?                      // CUSTOM 基数
  statsSalt    String?                   // 单篇重掷盐
}

/// 真实阅读逐日明细(V4.8.0 拟真放大用):仅记录真实事件的日期分布
model ContentDailyView {
  id        Int    @id @default(autoincrement())
  contentId Int
  date      String // 本地时区 YYYY-MM-DD
  views     Int    @default(0)
  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt
  @@unique([contentId, date])
  @@index([contentId])
}
```

## 6. 拟真不变量(测试锁死)

1. 关闭开关 → 展示值 == 真实值(逐字节零影响)
2. `statsMode=OFF` → 该篇 == 真实值
3. **单调不减**:now 变大,三个展示值都不减小
4. **刷新不变**:同输入同输出(确定性)
5. 新文(1 小时内)有值但很小;30 天 ≈ baseViews ±35%
6. 篇间量级不同:50 篇样本的 min < 中位数 < max,且极差 > 2 倍
7. 比例约束:`点赞 ≤ 阅读`、`转发 ≤ 点赞`、`收藏 ≤ 阅读`、整数非负;默认参数下 `收藏 ≤ 点赞`
8. 延迟释放:单次真实阅读当天释放 < 60%,5 天内接近 100%
9. 换 `seedSalt` → 曲线变化(重掷生效)
10. `CUSTOM` 基数被采纳(与基数量级一致)

## 7. 风险与边界

- **不碰真实数据**:拟真只改展示,`viewCount` 等真实列永不因拟真而变(反向也成立)。
- **不引入定时任务**:读时计算,无 cron、无补偿脚本。
- **性能**:列表页多一次 `ContentDailyView` 查询(有 `contentId` 索引,且只有发生过真实阅读的内容才有行);纯计算 O(天数×篇数),单页 < 1ms 量级。
- **关闭即隐身**:关掉开关后,任何地方都不会残留拟真数字。
- **合规提示**:拟真数据属运营手段;总开关默认关闭,由站点所有者在知情前提下自行开启。

### 开发中自检发现并修复的两处问题

1. **首发当天"偷跑"43% 的量**:原按自然日切分窗口,上午 9:30 发布的文章到 10:30 已"继承"当天过去的 9.5 小时 —— 自检实测篇#1009 首小时 198 阅读,明显不像真的。
   改法:时间锚点改为**发布时刻**,第一个 24h 窗口 = [发布, 发布+24h)。修复后首小时 3~23 阅读(按人气高低)。
2. **草稿/下架内容也在长阅读量**:后台列表实测草稿篇显示 358 阅读。
   改法:状态非 `PUBLISHED` 一律回落真实值(算法加闸门 + 服务层透传 status),已补 3 条测试。

### 收藏量补齐(2026-09-20 追加,用户要求)

- 算法:`favoriteRate`(默认 1%)独立随机盐,`DisplayCounts` 增加 `favorites`;真实收藏 1:1 叠加。
- 接入:收藏接口回包、个人中心「我的收藏」、后台列表/编辑页对照均含收藏。
- 前台互动条此前**不传** `favoriteCount`(收藏按钮只在点击后才出现数字),现已传入 → 首屏即显示「收藏(N)」。
- 修掉一处真 bug:`resolveDisplayCountsById` 漏 `select favoriteCount` → 收藏接口回包拿不到"本次 +1"(被新增测试当场抓住)。

### 遗留风险 / 待定

- **默认关闭**:生产升级后前台与现在逐字节一致,需在「功能设置 → 拟真数据」手动开启。
- 已有真实阅读的历史内容(升级前),没有逐日明细 → 放大部分从 0 起算,但展示值有"不低于真实值"兜底,不会出现倒挂。
- 与真人行为的差异:拟真曲线**不看内容质量、渠道与转化**,同一天发布的文章量级差异仅由随机种子决定;如需按栏目/关键词差异化,可在后续版本给 `statsMode=CUSTOM` 批量设定。
- 存量真实阅读明细不做回填(无法知道历史阅读发生在哪天)。
