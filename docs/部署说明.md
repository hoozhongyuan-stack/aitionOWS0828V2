# AitionOWS 部署说明(交付文档 · v2.0.0)

> 面向客户运维人员。前置条件:一台自备服务器(2C2G 起)、公网 IP、域名(可选但建议)。
> 无需任何云存储 / 云数据库 / 第三方付费服务。

---

## 一、一键部署(Docker,推荐)

### 1. 安装 Docker

服务器上执行(已安装可跳过):

```bash
curl -fsSL https://get.docker.com | sh
```

### 2. 上传源码并启动

把整个项目目录上传到服务器(如 `/opt/aition-ows`),然后:

```bash
cd /opt/aition-ows
docker compose -f docker/docker-compose.yml up -d --build
```

首次启动容器会自动完成:创建数据/上传/备份目录 → `prisma migrate deploy` 建库建表 → 写入默认管理员与默认配置 → 启动服务。

### 3. 访问

- 前台:`http://服务器IP:3000`
- 后台:`http://服务器IP:3000/zh-CN/admin`
- 默认管理员:`admin` / `admin888` —— **首次登录后系统会强制提示修改密码,请立即修改**

### 4. 生产必改项

编辑 `docker/docker-compose.yml` 环境变量后重启:

| 变量 | 说明 |
|---|---|
| `AUTH_SECRET` | **必改,且为安全硬性要求**。仍是默认值时,登录/注册接口会直接拒绝服务(HTTP 503,fail-closed 防伪造会话)。换成长随机串:`openssl rand -base64 48` |
| `NEXT_PUBLIC_SITE_URL` | 站点正式地址(如 `https://www.example.com`),影响 sitemap/分享链接/密码重置链接 |
| `TRUSTED_PROXY_HOPS` | 前置可信反向代理层数(默认 1,对应本文 Caddy 方案)。**请勿在无反代的情况下直接把 3000 端口暴露公网**——此时限频/统计依赖的客户端 IP 可被请求头伪造 |

```bash
docker compose -f docker/docker-compose.yml up -d   # 重启生效
```

### 5. 绑定域名 + HTTPS(可选,建议)

`docker/docker-compose.yml` 中取消 Caddy 段注释,把 `docker/Caddyfile` 里的域名换成真实域名,重启即可自动签发 HTTPS 证书。

如改用 nginx 反代,除转发外还需:`client_max_body_size 420m;`(视频上传单文件上限 400MB,需预留 multipart 开销);Caddy 默认无请求体限制,无需配置。

## 二、数据与备份

所有数据都在项目目录下,**迁移服务器 = 拷贝整个目录**:

| 目录 | 内容 |
|---|---|
| `data/` | SQLite 数据库(app.db) |
| `uploads/` | 全部图片/视频/附件 |
| `backups/` | 后台一键备份的产物 |

这三个目录通过 Docker volume 挂载在宿主机,**重建/升级容器不丢数据**。

- 日常备份:后台「系统 → 备份」一键备份(数据库热备快照 + 上传文件 zip),建议下载异地留存。
- 恢复:停止容器 → 用备份的 `app.db` 覆盖 `data/app.db`、解压 uploads 覆盖 `uploads/` → 启动容器。

## 三、版本升级(1.x → 2.0.0+)

2.0.0 起数据库结构变更走标准迁移(`prisma/migrations` 基线已建立):

```bash
# 拉取新代码后重新构建启动,entrypoint 自动执行 migrate deploy(数据无损)
docker compose -f docker/docker-compose.yml up -d --build
```

- 旧库(1.x 时代)首次升级到 2.x 会自动补齐基线迁移,数据不受影响。
- 升级前建议先在后台做一次「完整备份」。
- **升级后必须确认 `AUTH_SECRET` 已替换**,否则登录接口保持 503(见 4)。

## 四、常用运维命令

```bash
# 查看日志
docker logs -f aition-ows

# 重启
docker compose -f docker/docker-compose.yml restart

# 升级(拉取新代码后)
docker compose -f docker/docker-compose.yml up -d --build

# 停止
docker compose -f docker/docker-compose.yml down    # 数据不受影响
```

## 五、非 Docker 部署(备选)

前置:Node.js ≥ 20。

```bash
npm install
cp .env.example .env        # 修改 AUTH_SECRET(必改)/ NEXT_PUBLIC_SITE_URL
npx prisma migrate deploy   # 按迁移建库(全新库会应用基线迁移)
npx prisma db seed          # 默认管理员与配置(幂等,只补缺失)
npm run build
npm run start               # 生产启动(默认 3000 端口)
```

建议用 pm2 守护:`pm2 start npm --name aition-ows -- run start`。

## 六、常见问题

| 现象 | 处理 |
|---|---|
| 登录/注册返回 503「安全密钥未配置」 | `AUTH_SECRET` 仍是默认值或未配置(2.0.0 起的安全机制)。设置为强随机串并重启 |
| 端口冲突 | 改 compose 里 `"3000:3000"` 左侧端口 |
| 忘记管理员密码 | 停容器后删除 `data/app.db` 会重置全站(慎用,数据清空);或用备份库找回 |
| 微信登录不可用 | 后台「功能设置 → 微信登录」填入开放平台 AppID/Secret 并启用;回调域名需在微信开放平台配置 |
| 上传提示类型不允许 | 后台「功能设置 → 上传限制」调整允许类型;视频单文件上限固定 400MB,图片等按「大小上限」配置 |
| 大视频上传失败/超时 | 检查反代 body 限制(nginx 需 `client_max_body_size 420m`);直连 3000 端口时检查防火墙 |
| 验证码/限频误伤(所有用户共享同一限频额度) | 通常是反代未正确传递客户端 IP:确认 `TRUSTED_PROXY_HOPS` 与真实反代层数一致 |
