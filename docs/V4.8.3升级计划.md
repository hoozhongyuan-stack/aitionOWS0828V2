# V4.8.3 升级计划 —— 页脚版权链接 · 登录页客服邮箱 · 右侧悬浮入口

> 状态:开发完成,本地验收中(生产仍是 4.8.2)
> 三个需求同批:两个小配置项 + 一个新功能

## 一、页脚版权跳转链接 + 登录页客服邮箱(用户需求)

**核实到的现状**:页脚版权文字此前被写死包在 `<a href="https://www.aition.art">` 里(V4.0.2 遗留),
部署到客户站点后是**指向模板作者旧域名的错误外链**;后台登录页第 95 行写死 `客服邮箱:leooohu@outlook.com`。

**改法**
- `BrandConfig` 新增 `copyrightUrl`(页脚版权跳转链接)与 `supportEmail`(客服邮箱),默认空串;
- 页脚:配置了链接且为 http/https 时渲染 `<a target="_blank" rel="noopener">`,否则渲染纯文本
  —— 空值不再产生外部链接;非 http/https(如 `javascript:`)被白名单拒绝;
- 登录页:客服邮箱经 `/api/flags`(公开运行时配置)下发,未配置则不渲染该行;
- 「功能设置」新增 **页脚与客服** 页签(排在拟真数据之后);品牌信息页版权输入框下加交叉提示。

**测试**:页脚链接开关/白名单/兜底 7 条 + flags 下发 2 条。
**顺带修**:V4.8.0 的一条自测用例跨两篇内容比较取整差值,量级小时被 ±1 抹平(偶发失败),
改为同一篇内容两个时刻的确定性比较。

## 二、右侧悬浮入口(用户需求)

**需求还原**:网站右侧固定悬浮,最多两条;三条类型 —— 拨号 / 关联表单 / 微信二维码。
**用户确认的设计选择**:表单用「当前页弹层内嵌填表」(不跳页,需新增公开表单读取接口);
二维码由悬浮入口自己上传(不复用品牌信息里的社交二维码);移动端显示但缩成右下角圆钮;
配置入口放**品牌信息**页。

**改法**
- 配置:`BrandConfig.floating: FloatingEntry[]`(type/iconUrl/label + tel/formId/qrcodeUrl),空数组=不渲染;
- 纯逻辑 `src/lib/floating.ts`:`telHref`(号码净化,仅保留数字与 + - 空格 括号)、
  `normalizeFloatingEntries`(丢脏条目 + **封顶 2 条** + 提示文字截断 20 字)、`buildFloatingItems`(表单解析);
- 公开接口:`GET /api/form/[slug]` —— 只返回**启用中**表单的 slug/name/fields,不含提交数据;
- 服务:`getEnabledFormsByIds`(layout 把 formId 解析成表单;停用/删除 → 该入口自动消失,不留死链);
- 前台组件 `floating-actions.tsx`:桌面右侧竖排(悬停出文字)、手机右下圆钮(点开展开);
  tel 项是原生 `<a href="tel:">`(不依赖 JS,移动端直接拉起拨号盘);form/qrcode 走弹层,
  支持 Esc 与点遮罩关闭;form 弹层复用 `FormRenderer`(校验/提交/防重复全部继承);
- 后台:品牌信息页新增「悬浮入口」卡片(类型下拉 + 图标上传 + 号码/表单下拉/二维码上传 + 提示文字 + 删除),
  表单下拉只列启用中的表单。

**测试**:纯逻辑 13 条(号码净化/脏配置清洗/条数封顶/表单缺失丢弃)+ 组件 8 条
(未配置不渲染 / tel 原生链接 / 二维码弹层 / Esc 与遮罩关闭 / 表单弹层加载与 404 提示)+ 表单 GET 4 条。
