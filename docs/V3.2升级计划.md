# AitionOWS V3.2 升级计划（详细稿 · 待审核）

> 两项已确认需求：①前台布局预设（方案 A · 轻量）②GEO 监测一期。微信 JS-SDK 分享卡片记录为后续候选（暂不做）。本文为详细实施计划，**经审核后启动开发**。

---

## 需求一：前台布局预设（方案 A · 轻量）

### 目标
首页/栏目页提供预置布局模板与区块显隐开关，管理员后台选择保存即生效；核心功能零改动。

### 1. 布局配置模型（存 Setting，无新表/无迁移）
```
Setting(group="layout", key="home")     → {"preset":"grid|hero-list|split","sections":{"latest":true,"banners":true,...}}
Setting(group="layout", key="category") → {"preset":"list|magazine","sections":{"banners":true,...}}
```
- 未知键回退默认（存量兼容：无配置 = 现状布局，升级零变化）

### 2. 首页布局预设（3 套）
| 预设 | 排布 |
| --- | --- |
| grid（现状默认） | 轮播 Hero → 最新动态网格 → (页脚) |
| hero-list | 全宽 Hero(标题/副题/CTA 居中大图) → 最新动态**列表式**（横向条目）→ CTA 横幅 |
| split | 左右分屏 Hero(图/文) → 最新动态两列 → 联系卡 |

### 3. 栏目页布局预设（2 套）
| 预设 | 排布 |
| --- | --- |
| list（现状默认） | 头图(可选) → 卡片网格 + 分页 |
| magazine | 杂志式：首条大图特写 + 其余双列 + 侧栏(最新/热门) |

### 4. 区块显隐开关（一期粒度）
首页：最新动态 / 轮播；栏目页：头图。开关只控制显隐，不改变数据链路。

### 5. 后台界面
「站点配置」新增**页面布局**页：首页/栏目页两个卡片，各含布局预设选择（缩略示意）+ 区块开关 + 保存即生效（沿 Setting 缓存管线）。

### 6. 前台实现
- 服务层：`getLayoutConfig(page)` 读取+合并默认值
- 首页 `page.tsx`：按 preset 分支渲染（组件复用为主，新增 2~3 个布局变体组件：HeroList/SplitHero/CTABanner）
- 栏目页：同上（magazine 变体组件）
- 双主题协同：所有变体组件自动继承 classic/aurora（纯用现有变量与 aurora 作用域）

### 7. 验收（AC 摘要）
- 切换布局预设：前台排布即时变化；切回默认与升级前一致
- 区块显隐：关闭后前台不再渲染该区块（数据不删）
- 双主题 × 预设矩阵全页走查（2 主题 × 3+2 预设）
- 回归：156 测试全绿 + build

工作量：**M**（约 5~7 天）

## 需求二：GEO 监测一期（自控数据 · 零外部依赖）

### 目标
让管理员"可见、可监控、说得上来渠道和时间"：
- **谁在爬**：AI 爬虫（豆包/ChatGPT/Perplexity/Claude/谷歌等）访问你站的引擎、页面、时间
- **谁被带来看**：AI 渠道（chatgpt.com/perplexity.ai/doubao.com…）引荐访客与落地页

### 1. 关键技术决策（已核实打点链路）
- **AI 爬虫不执行 JS**，现有客户端埋点（/api/track）抓不到爬虫——记录点放在**服务端布局**：`[locale]/layout.tsx`（每请求必经）读 `headers()` 的 UA → 匹配 AI 爬虫白名单 → **异步写库（不阻塞渲染）**
- AI 引荐：同位置读 `referer` 头 → 匹配 AI 渠道白名单 → 记录落地页
- 排除 admin/_next/uploads 等非内容路径

### 2. AI 爬虫识别清单（一期，内置可维护）
GPTBot / OAI-SearchBot / ChatGPT-User / PerplexityBot / Perplexity-User / ClaudeBot / Claude-User / Google-Extended / GoogleOther / Applebot-Extended / **Bytespider(字节·豆包)** / DeepSeekBot 等（常量表，后续可后台增补）

### 3. AI 引荐渠道清单（一期）
chatgpt.com / perplexity.ai / doubao.com / yuanbao.tencent.com / grok.com / copilot.microsoft.com / gemini.google.com / kimi.moonshot.cn 等

### 4. 数据模型（一次迁移，两表均带 upsert 累加语义）
```
AICrawlStat(bot, date, path, count)      unique(bot,date,path)   —— 爬虫×日期×路径 计数
AIReferralStat(source, landing, date, count) unique(source,landing,date) —— AI 引荐 计数
```
- 明细粒度到路径，足以回答「某天某引擎爬了/引荐到某篇内容」
- 保留策略：90 天前数据由运维 SQL 清理（二期做自动清理任务）

### 5. 后台「GEO 监测」页（新菜单，admin 权限）
| 区块 | 内容 |
| --- | --- |
| AI 爬虫趋势 | 按引擎分色的逐日曲线（近 7/30 天，沿 V3.1 看板交互） |
| 被爬页面 Top 10 | 路径 × 引擎 × 次数（"某篇内容被 GPTBot 爬了 6 次"） |
| AI 渠道引荐 | 来源引擎 × 落地页 × 次数（"某天豆包带来 3 个访客，落地 iPhone 17 Pro"） |
| 自检卡 | llms.txt / robots.txt / 各引擎 UA 白名单版本状态 |

### 6. 验收（AC 摘要）
- 用模拟爬虫 UA 请求页面 → AICrawlStat 累加且后台页可见"某引擎某天爬某路径"
- 带 AI 渠道 referer 访问 → AIReferralStat 累加并出现在 GEO 监测页
- admin 路径/非白名单 UA 不记录；渲染延迟 < 50ms（异步写不阻塞）
- GEO 监测页仅 admin 可见；趋势/Top/引荐三视图可用

工作量：**M**（约 5~7 天，含测试与走查）
