# WorkBuddy 对接方案（初稿 · 待审核）

> 目标：在 WorkBuddy 里写好文章（中英双语 + 配图）→ 一键推送到 aition.art 官网。
> 性质：试验性项目，单独分支开发，验证后再决定是否合并主线。
> 状态：**初稿待用户审核，尚未开工**。基线＝当前 main（v4.2.0，已部署生产）。

---

## 一、定位与目标

**要解决的问题**：目前发文需要在后台手工粘贴正文、逐字段填写、手动上传配图、中英各做一遍。希望变成——在 WorkBuddy 里写稿（AI 帮查资料、润色、翻译、生成配图），写好后一句话推送，官网自动完成格式转换、字段校验、图片上传与入库。

**关键的定位判断（已与用户确认）**：
这是**"人在环"的推送通道**，不是"AI 全自动写稿发布"。用户写、用户审，机器只负责搬运、格式转换和入库。内容质量的三层把关（写作规范前置 / 推送硬校验 / 发布前人工过眼）都建立在这个定位上。

**不做的事**：
- 不给 WorkBuddy 网站后台的网址 + 主账号密码（等于把站点配置/用户/备份下载全部交出，且 cookie 认证形态不适合程序调用）
- 不上架腾讯开放平台做完整 Connector（那是面向"给所有用户用"的形态，自用只需本地自配）

## 二、总体架构（四层）

```
┌─ ① 内容层（用户侧）────────────────────────────────────┐
│  在 WorkBuddy 里写稿：中文 + 英文 + 配图提示词           │
│  规范由「官网文章规范」技能保证（写作时即合规）           │
└──────────────────────┬───────────────────────────────┘
                       │ 一句话："推到官网"
┌──────────────────────▼───────────────────────────────┐
│  ② 通道层：本地 MCP Server（跑在用户 Mac 上）            │
│  6 个工具 · Markdown→白名单 HTML · 字段校验 · slug 查重   │
│  会话：Bearer token（新增支持），凭证只存本地            │
└──────────────────────┬───────────────────────────────┘
                       │ HTTPS（Bearer token）
┌──────────────────────▼───────────────────────────────┐
│  ③ 权限层：专用 STAFF 子账号（只勾 content 权限组）       │
│  凭据泄露最坏损失＝内容被改；操作全进 admin-logs 审计      │
└──────────────────────┬───────────────────────────────┘
                       │ PUT /api/admin/contents
┌──────────────────────▼───────────────────────────────┐
│  ④ 内容层（官网侧）：草稿 DRAFT → 列表页定制发布          │
│  发布节奏：手动发布 / SCHEDULED 定时到点自动上线（原生）   │
└──────────────────────────────────────────────────────┘
```

**发布节奏的两种选择**（工具与系统都支持）：

- **手动**：推送为草稿 → 用户在后台点发布
- **定时**：推送时带 `publishAt`（status=SCHEDULED）→ 系统到点自动上线

> 定时发布用系统原生的**懒惰晋升**机制（`src/server/content/index.ts:24-30`：任何读路径把到点内容晋升为 PUBLISHED），**不依赖常驻定时器、不依赖用户电脑开机**，比 WorkBuddy 侧的 rrule 定时任务更可靠。

## 三、系统改动详设（三项）

### 3.1 Bearer token 支持（约 0.5 天）

**现状**：`POST /api/admin/auth/login` 签发 JWT 写入 httpOnly cookie（`src/app/api/admin/auth/login/route.ts:60`），`getAdminSession()` 只从 cookie 读取（`src/lib/auth/session.ts:26`）。非浏览器程序需模拟登录 + 手工维持 cookie + 7 天过期重登。

**改动**：
- `getAdminSession()` 增加读取分支：先读 cookie，没有则读 `Authorization: Bearer <token>`
- 新增一个签发长期令牌的入口（仅 OWNER；一次性 CLI 脚本或后台按钮均可，倾向脚本，避免扩大后台面）
- **权限边界不变**：同一套 JWT 签名校验 → 同样的 `requirePerm` 守卫，子账号仍只勾 content

**验收**：
- `curl -H "Authorization: Bearer <token>" /api/admin/contents` 正常返回
- 原有 cookie 登录流程零回归
- 无 token / 错误 token / 过期 token 均返回 401

**风险**：长期 token 泄露有效期长 → 用最小权限子账号 + 可吊销（换密即失效）缓解。

### 3.2 列表页"定制发布时间"列 + "定制发布"操作（约 1 天）

**现状**：定时发布藏在编辑页深处（改状态 + 选时间 + 保存）；列表页 8 列中没有发布时间。

**改动**：
- **列**：列表新增"发布时间"（数据现成，`listContentsAdmin` 返回 Prisma 全字段，纯前端改动）
- **操作**：新增"定制发布"弹窗（选日期时间）+ 快捷项"立即发布"
- **新端点**：`PATCH /api/admin/contents/schedule`，只收 `{ id, action, publishAt }`，只改 status 与 publishAt

> **为什么不复用现有 PUT**：`PUT /api/admin/contents` 是整体覆盖语义，要求完整字段（slug/translations 全文等），只改时间却走它会导致字段被清空——与 V4.1.2 价格/SPU 被 zod 静默剥离的生产事故同类风险。

**publishAt 语义现状（需知）**：定时到点晋升时保留时间（当作实际发布时间记录）；编辑页直接设已过时间则被清空。因此已发布文章的"发布时间"列会有"有值/空"两种。空值显示创建时间即可（本方案不改动既有写入语义）。

**验收**：列显示正确；定制发布设定未来时间 → 状态变 SCHEDULED → 到点自动上线；操作写入 admin-logs。

### 3.3 前台预览功能（约 1.5～2 天）

**现状**：后台无前台预览（仅 UGC 投稿有弹窗预览；内容管理页只有 Tiptap 编辑态）。

**改动**：
- 前台详情路由加预览分支（复用同一套模板 → 真·所见即所得），可预览 **DRAFT / SCHEDULED / OFFLINE** 全部未公开状态
- 后台编辑页 + 列表页加"前台预览"入口（新窗口打开）

**隔离要求（重点，因为本站有 GEO 能力）**：
- 预览页必须 `noindex, nofollow`，不得进 sitemap
- **绝不能进 llms.txt**（`src/server/content/llms.ts` 在组装该文件，草稿内容混入＝向 AI 引擎投喂未发布内容）
- 不污染 GEO 监测数据
- 第一版**仅管理员登录可见**（`getGuardedAdmin()` 鉴权）；未来若要分享给外部人看，再加签名链接（等于开公网入口，需单独设计）

**验收**：草稿/定时/下架内容均可预览；未登录访问被拒；页面 meta 含 noindex；llms.txt 与 sitemap 不含未发布内容。

## 四、MCP Server 设计（约 1 天）

**位置**：官网仓库内 `tools/workbuddy-mcp/`（独立运行，但与 API 形态同源，便于版本管理）
**形态**：stdio，经 `~/.workbuddy/mcp.json` 自配接入（免上架审核）

| 工具 | 作用 | 对应接口 |
|---|---|---|
| `list_categories` | 列出可投稿栏目（含各语言名称） | GET /api/admin/categories |
| `list_articles` | 查已有文章（防重复选题） | GET /api/admin/contents |
| `get_article` | 读单篇（改稿用） | GET /api/admin/contents?id= |
| `create_article` | 新建（**默认 DRAFT**） | PUT /api/admin/contents |
| `update_article` | 更新（必带 id） | PUT /api/admin/contents |
| `upload_image` | 上传配图（封面/内文） | POST /api/admin/upload |

**核心处理逻辑**：
1. **Markdown → 白名单 HTML**：允许 `p/br/h2/h3/blockquote/pre/code/strong/em/s/del/u/ul/ol/li/a/img/video/table`（`src/lib/sanitize.ts:13-23` 实测）；**没有 h1**（标题走 title 字段，正文从 h2 起）；内联 style 一律剥离
2. **硬校验**（不合格拒绝并说明缺什么）：标题/摘要/正文/栏目/作者/至少一种语言的翻译；slug 自动生成 + 查重；`publishAt` 若传则校验时间格式
3. **配图**：接收本地文件路径 → 上传 → 替换正文中的图片引用为官网 URL
4. **令牌管理**：读取本地配置的 Bearer token；401 时给出可操作提示（而非静默重试）

**推送回执**：返回后台编辑页链接 + **前台预览链接**（3.3 完成后）→ 用户点开一眼定夺。

## 五、WorkBuddy 侧配置（约 0.5 天）

**5.1 mcp.json**（本地自配，凭证不进对话）

```json
{
  "mcpServers": {
    "aition-ows": {
      "command": "node",
      "args": ["/path/to/tools/workbuddy-mcp/index.js"],
      "env": {
        "AITION_API_BASE": "https://aition.art",
        "AITION_API_TOKEN": "<专用子账号的长期令牌>"
      }
    }
  }
}
```

**5.2「官网文章规范」技能（1 个技能，内部分四节）**

> 为什么是 1 个而不是多个：写作、配图、推送是一条流水线的三段，agent 一次任务里要全部用上；拆开会来回引用，且多技能会互相竞争触发时机。试验阶段跑通后再拆。若 WorkBuddy 支持技能附属文件，较长的图片提示词模板外置，主文件引用。

- **① 写作规范**：正文从 h2 起（无 h1）、禁用内联样式、表格/图片/链接可用、首段摘要、小标题分段、关键词布局（GEO）
- **② 配图规范**（参数来自代码实测）：

| 项 | 约束 | 技能中的要求 |
|---|---|---|
| 封面图 | 前台 `object-cover` 裁剪：精选卡片 2:1、普通卡片 16:9（`src/components/site/content-card.tsx:49`），首页展示位 4:3 | 生成 1600×900（16:9），**主体居中且四周留安全区**，兼容各种裁切 |
| 内文图 | `.rich-content img` 宽度自适应（`src/styles/globals.css:129`），无固定像素要求 | 宽 1200px 左右，16:9 或 4:3，别用样式控制大小 |
| 体积 | 上传上限 10MB，允许 jpeg/png/webp/gif/svg（`src/lib/config/index.ts:98-113`） | webp 或 jpg，控制在 1～2MB |
| 风格 | 官网视觉＝深藏青夜空 + 玫瑰红/紫罗兰/青色极光 | 提示词模板固化这套视觉关键词，避免风格游离 |
| 数量 | —— | 封面必 1 张；正文按 h2 分段配 2～4 张 |

- **③ SEO/GEO**：seoTitle / seoKeywords / seoDesc 的写法与长度
- **④ 推送流程**：调哪个工具、参数怎么给、**中英双语各一份**（同一 content 记录的 translations）、默认草稿、拿到预览链接后怎么回报用户

**5.3 专用子账号**：后台新建 STAFF 账号（如 `workbuddy-bot`），权限组**只勾 content**（内容、栏目、导航、轮播图、文件、表单）。

## 七、风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 长期 token 泄露 | 内容被篡改 | 最小权限子账号（仅 content）+ 换密即吊销 + admin-logs 可追溯 |
| 预览功能泄漏未发布内容 | 草稿被搜索引擎/AI 引擎抓取 | 仅管理员可见 + noindex + sitemap/llms.txt 双重隔离 + 验收专项检查 |
| Markdown 转换后格式不符预期 | 排版走样 | 白名单转换 + 推送后回预览链接人工过眼（不自动发布） |
| 英文版质量 | 海外 GEO 效果受损 | 技能规范约束 + 建议抽查关键篇目（**非阻塞项**） |
| WorkBuddy 生成的图片产物形态未知 | 上传环节待定 | 实验时确认（本地文件路径 or 需手动导出）；工具按"接收本地路径"设计 |
| 自动发布内容质量 | 品牌形象 | 默认 DRAFT；定时发布需用户主动设置 |
