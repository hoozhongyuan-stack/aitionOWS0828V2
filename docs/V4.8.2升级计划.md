## 问题 1:robots AI 组与 GEO 识别表收口为单一事实来源(方案 A)

### 改法

新增依赖无关模块 `src/lib/seo/ai-crawlers.ts`:

```ts
export interface AiCrawlerEntry { token: string; name: string }
/** AI 爬虫单一事实来源:robots 分组与 GEO 识别表都从这里派生 */
export const AI_CRAWLERS: readonly AiCrawlerEntry[] = [
  { token: "GPTBot", name: "GPTBot (OpenAI)" },
  ...
  { token: "Applebot-Extended", name: "Applebot-Extended (Apple 智能)" }, // ⚠️ 必须排在 Applebot 之前
  { token: "Applebot", name: "Applebot (Apple 搜索/Siri)" },             // ③ 本次统一进 AI 口径
  ...
];
```

- `src/app/robots.ts` → `userAgent: AI_CRAWLERS.map(c => c.token)`(**9 → 19 条**)
- `src/server/geo/index.ts` → `export const AI_BOTS = AI_CRAWLERS.map(c => ({ match: c.token.toLowerCase(), name: c.name }))`
  —— 匹配语义与今天逐字相同(小写包含匹配),**统计口径零变化**,唯一新增是把 Applebot 计入 AI 引擎(用户已确认)

### 两个必须处理的细节

1. **匹配顺序**:`applebot` 是 `applebot-extended` 的子串。表中必须把 `Applebot-Extended` 放在 `Applebot` **之前**,否则 Applebot-Extended 的 UA 会被错认成 Applebot(现有表只有 -Extended 所以没暴露;加入 Applebot 后必然踩到)。
2. **后台文案是硬编码**:`geo-monitor/page.tsx:241` 写着「白名单覆盖国内外 18 个引擎」——改为从 `AI_BOTS.length` 动态生成,避免又一次两处漂移。

### 测试(新增 `tests/seo/robots-ai-crawlers.test.ts`)

- robots 的 AI 组 token 集合 **等于** `AI_CRAWLERS` 的 token 集合(19 个);
- **回归守卫**:`AI_BOTS` 的每个 match 都能在 robots AI 组里找到对应 token —— 这条断言就是本次 bug 的守卫;
- `aiCrawlAllow=false` → AI 组为 `Disallow: /`;`=true` → `Allow: /` + `Disallow: /admin`、`/api`;
- UA 顺序守卫:`Applebot-Extended/1.0` 必须被识别为 Applebot-Extended(而非 Applebot)。

## 问题 2:GEO 记录点改按路径段判断

### 改法

`src/server/geo/index.ts` 新增纯函数(可单测):

```ts
const GEO_EXCLUDED_SECTIONS = new Set(["admin", "api", "_next", "uploads"]);

/** 是否应记入 GEO(locale 之后的第一段命中排除段才排除;slug 里含 api/admin 不再误伤) */
export function isGeoRecordablePath(reqPath: string, locale: string): boolean {
  const segments = reqPath.split("/").filter(Boolean);
  const section = segments[0] === locale ? segments[1] ?? "" : segments[0] ?? "";
  return !GEO_EXCLUDED_SECTIONS.has(section);
}
```

`src/app/[locale]/layout.tsx:92` 改为 `const isSitePath = isGeoRecordablePath(reqPath, locale);`

### 与「正则加锚点」的区别(为什么不那样做)

加锚点(`^\/(zh-CN|en)\/(admin|api)`)对"栏目 slug 恰好是 `api`"仍会误伤(段本身叫 api 属正常内容);按段判断只排除**路由位置**上的 admin/api,内容页无论 slug 叫什么都能记录。

### 测试(新增 `tests/server/geo-path-filter.test.ts`,12 条)

覆盖:正常文章/栏目、`api-design`、`api-case`、`admin-guide`、`uploads-guide`、段正好是 `api`/`admin` 的内容页、`/zh-CN/admin/*`、`/zh-CN/api/*`、`/_next/*`、`/uploads/*`、`/zh-CN`、`/en/c/uploads-guide`(多语言)。

## 问题 3:访客口径 A+B

### A 部分 —— 竞态与命名

- 新增表 `AIReferralVisitor { id, source, date, visitorId, landing, createdAt, @@unique([source, date, visitorId]) }`
  (与项目既有做法一致:靠**唯一约束**判定"首次",取代现在的"先 aggregate 再写"竞态逻辑)
- 写入时机:同一个 `$transaction` 内插入该表 —— 插入成功 = 新访客 → 对应落地页行 `visitors + 1`;唯一冲突 = 老访客 → 只累加 `count`
- 后台列名:「访客」→**「独立访客」**,并加 tooltip:「按 渠道+日期+匿名访客标识 去重;同一人当天从同一渠道多次到访只计 1」

### B 部分 —— 真·独立访客(客户端上报)

**现状**:引荐在服务端按 `Referer` 头识别(layout),服务端**看不到** `aition_vid`(它存在 localStorage),因此无法按人去重。

**改法**:
1. `src/components/site/page-tracker.tsx`:每次页面加载只上报一次初始 `document.referrer`(用模块级标记,避免 SPA 内部跳转重复上报),随现有 `{ path, visitorId }` 一起 POST;
2. `/api/track` 的 zod 增加可选 `referrer`(≤ 2048);命中 AI/传统搜索引荐白名单时调用 `recordReferral(source, landing, kind, visitorId)`;
3. `recordReferral` 增参 `visitorId?`:`visitors` 只在**新访客行插入成功**时 +1;
4. `layout.tsx` 中**移除引荐识别**(只保留爬虫识别 —— 爬虫不跑 JS,必须留在服务端)。

**代价(明确写下)**:引荐统计从"服务端、不依赖 JS"变为"客户端、依赖 JS"。取舍理由:只有客户端拿得到匿名访客标识,想要真 UV 就必须走客户端。爬虫统计不受影响。

**合规**:隐私政策的"收集字段"表需**补一行**「来源页地址(referrer)、匿名访客标识」——已确认当前政策**没有**这一项(只有 `aition_vid` + 页面路径 + 访问时间)。文档在 `docs/legal/02-用户隐私政策.md`,我出草稿,你确认后再改。

### 历史数据

`visitors` 列的历史值语义是"当日首达标记",与新的"独立访客"不可比。**建议保留历史不动**,新口径自补丁上线日起生效(文档与 tooltip 里说明);若你要清空历史以获得干净口径,我另跑一次定向清理(需你明确指令)。

### 测试

- `recordReferral`:同访客同日两次 → visitors 只 +1、count +2;不同访客 → 各 +1;同访客跨日 → 各日 +1;
- **并发守卫**:`Promise.all` 同访客并发 10 次 → visitors 恰好 +1(唯一约束生效);
- 无 visitorId 时只累加 count(兼容旧调用);
- `/api/track` 带 referrer:命中 DeepSeek 引荐 → 落库 source 正确、landing 正确;内部 referrer 不记录。
