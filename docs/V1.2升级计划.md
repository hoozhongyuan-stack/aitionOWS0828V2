# AitionOWS V1.2 升级计划

> 基于《测试反馈.docx》整理，并对照当前代码库（Next.js + Prisma）定位根因后制定。共 8 项缺陷修复 + 4 项新增需求。此文档为规划稿，**待确认后再执行开发**。

---

## 一、缺陷修复

### 1. 前台语言切换后，导航栏文案不跟随切换
**根因（已定位）**：`src/server/content/nav.ts` 中 `resolveLabel()` 的取值优先级是 `labelI18n[当前语言] → item.label → 栏目名`。`item.label` 是一个**不区分语言的固定字段**（创建导航项时按默认语言填入）。当后台在"导航"页只填写了中文文案、未补齐英文 `labelI18n`，切到英文站时会跳过栏目名（其英文翻译其实是齐的，如截图 ABOUT US），直接兜底到 `item.label`（中文），于是导航栏"看起来没切"。
**方案**：调整回退顺序——对于**关联了栏目**的导航项，`labelI18n` 缺失当前语言时，优先兜底到栏目名的对应语言翻译（已存在且已维护），而不是 `item.label`；`item.label` 仅作为自定义链接（未关联栏目）时的兜底。
**涉及文件**：`src/server/content/nav.ts`（`resolveLabel`/`toLink`）。
**工作量**：S（小改动，无需迁移库表）。

### 2. 后台上传图片处未标注建议尺寸
**方案**：`UploadField` 组件增加可选 `hint`（建议尺寸文案）属性，在各调用处（LOGO/favicon、内容封面图、品牌/主题相关上传等）按场景传入建议尺寸说明。
**涉及文件**：`src/components/admin/upload-field.tsx` + 各调用页（`brand/page.tsx`、`content/page.tsx`、`theme/page.tsx` 等）。
**工作量**：S。
**待确认**：各处建议尺寸的具体数值（LOGO、封面图、favicon 等），需要产品/设计给出一份尺寸规范表，否则先用通用占位建议（如"建议 1200×630px，≤2MB"）。

### 3. 首页副标题文案（"高度自定义·本地部署·AI 检索友好"）后台无处设置
**排查**：该文案目前落在首页模板里（Hero 区块），不是走内容/栏目系统。
**方案**：将其纳入"品牌信息"或新建"首页设置"分组的可配置字段（支持中英文），后台填写后 Hero 区读取该配置渲染。此项与下方"新增需求 1（轮播图）"是同一个 Hero 区域，建议合并到轮播图/首页 Hero 改造中一并做，避免重复改两次模板。
**工作量**：S（若独立做）/ 并入需求①后为增量工作。

### 4. 表单提交按钮显示英文占位符 "form.submit"
**根因（已定位）**：`messages/zh-CN.json` 与 `messages/en.json` 的 `form` 命名空间下**没有 `submit` 这个 key**（只有 `required/submitSuccess/submitFailed/uploadFile/selectPlaceholder`）。`src/components/site/form-renderer.tsx:175` 调用 `t("submit")`，next-intl 找不到 key 时按约定回显 `"form.submit"`。
**方案**：在两份 messages 文件的 `form` 节点下补充 `"submit": "提交"` / `"Submit"`。同时顺带检查 `submit-form.tsx`（用户投稿表单，同样调用 `t("submit")`）是否共用同一 key，需一并确认其命名空间。
**工作量**：XS（配置补齐，无代码逻辑变更）。

### 5. 维护模式开关打开后前台仍可访问
**现状核查**：`src/middleware.ts` + `src/app/api/flags/route.ts` 的设计逻辑本身是对的（读取 `brand.maintenance` → 中间件 rewrite 到 `/maintenance`，`fail-open` 兜底、`cache: no-store`）。因此不是架构性缺陷，更像是以下几种可能之一：
  - 品牌设置保存后，服务端配置缓存（`getBrandConfig` 内部很可能有内存缓存）未失效，导致 `/api/flags` 短时间内仍返回旧值；
  - 测试时用管理员会话在 `/admin` 下操作，`/admin` 路径本身在 `EXEMPT_PREFIXES` 里不受影响，容易造成"感觉没生效"的错觉，需要用**前台无痕/未登录窗口**复测确认现象；
  - 也可能是 fail-open 分支被触发（如 `/api/flags` 请求超时或报错）。
**方案**：先在开发环境复现 + 加日志定位是缓存未失效还是请求失败，再针对性修复（大概率是保存维护模式配置时需要显式清缓存）。
**工作量**：S～M（需要先复现定位，无法仅凭代码静态判断）。

### 7. 前端找不到"用户投稿"入口；投稿后无法查看审核状态
**排查**：`Category` 表已有 `allowSubmit` 字段（后台栏目管理已支持勾选"可投稿"，如截图 ACTIVITY 栏目），且 `/submit`、`/submissions` 两个前台页面**已经存在**，只是没有任何入口链接到它们——栏目详情页 `c/[slug]/page.tsx` 没有读取 `allowSubmit` 渲染"我要投稿"按钮，页头/用户菜单也没有链接到"我的投稿"。
**方案**：
  - 在栏目详情页（`allowSubmit=true` 时）渲染"我要投稿"入口，跳转 `/submit?category=slug`；
  - 登录态用户菜单（页头 `SiteHeader`）增加"我的投稿"入口，跳转 `/submissions`，展示审核状态（待审/通过/驳回）。
**涉及文件**：`src/app/[locale]/(site)/c/[slug]/page.tsx`、`src/components/site/header.tsx`，`/submissions` 页面已存在，按需微调展示字段。
**工作量**：S。

### 8. 后台可修改互动数据（阅读量/点赞/转发），应仅可查看
**根因（已定位）**：`content/page.tsx` 的"修改互动统计"弹窗直接提供 `viewCount/likeCount/shareCount` 三个可编辑输入框 + "全部清零"按钮，对应写接口在 `src/app/api/admin/contents/route.ts`。
**方案**：移除该弹窗的编辑能力，列表页互动数据改为纯展示；同时禁用/移除对应的写接口（或至少去掉前端入口 + 后端加权限校验兜底，防止绕过前端直接调 API 篡改）。
**待确认**：是否**完全禁止**编辑（含超级管理员），还是保留"仅超管可修改，普通管理员只读"这类分级权限？这会影响改动范围（纯前端隐藏 vs. 权限校验体系）。
**工作量**：S（纯前端隐藏）～M（如需权限分级）。

## 二、新增需求

### ① 首页顶部通屏轮播图（Hero 背景轮播）
**现状**：代码库中**目前没有任何轮播图/Banner 相关的模型或组件**，是全新功能。
**方案**：
  - 新增 Prisma 模型 `Banner`（字段：图片 URL、跳转链接（可选）、排序、启用状态、多语言：如需要标题/文案可分离出 `BannerTranslation`）；
  - 后台新增"轮播图管理"页面（列表 + 增删改 + 排序 + 上传，上限 5 张，如需求所述）；
  - 首页 Hero 区改造为轮播容器，导航栏叠加在轮播图上方作为背景（半透明/暗化处理保证文字可读），支持自动播放 + 手动切换；
  - 与"缺陷 3"的 Hero 副标题文案合并处理，一并纳入本次 Hero 模板重构。
**待确认**：
  - 轮播图与"缺陷 3 的副标题/主标题文案"是否也要做成可配置（当前若合并，标题/副标题可能需要挂在 Banner 或独立的"首页设置"上，需要明确归属）；
  - 轮播切换动效、是否需要移动端单独适配的图片。
**工作量**：M～L（新表 + 迁移 + 后台页面 + 前台模板重构）。

### ② 社交账号支持二维码图片
**现状**：`BrandConfig.socials` 目前是 `{ name: string; url: string }[]`，只有名称+外链。
**方案**：`socials` 结构扩展为 `{ name, url, qrcodeUrl? }`，后台"社交账号"每一项增加二维码图片上传（可选）；前台页脚渲染时，若配置了二维码则展示为可悬浮/点击查看大图的图标，仍保留点击跳转 `url` 的能力。
**涉及文件**：`src/lib/config/index.ts`（类型定义）、`brand/page.tsx`（后台表单）、`footer.tsx`（前台渲染）。
**工作量**：S～M。

### ③ 指定文字的字体颜色支持后台自定义
**排查**：截图中标出的"首页动态卡片摘要文字、页脚社交/联系方式/协议链接"等蓝色文字，经查代码，`content-card.tsx`/`footer.tsx` 里这些元素**大多没有显式颜色类**，很可能是走了浏览器/全局默认的链接蓝色，并**没有真正跟随**现有主题配置里的"主色"（`ThemeConfig.primary`，其定位本就是"品牌主色，按钮、链接、强调元素"）。
**方案（二选一，需确认）**：
  - **方案 A（推荐，改动小）**：将这些文字元素统一接入已有的 `primary` 主题色变量，不新增字段——后台"主题外观"里已经能改主色，改完这些文字会跟着变；
  - **方案 B**：新增独立的"链接/强调文字颜色"字段，与按钮主色解耦，允许单独设置。
**待确认**：采用 A 还是 B——A 更快上线且逻辑更统一，B 灵活度更高但要新增配置项和迁移。
**工作量**：S（方案 A）/ S～M（方案 B）。

### ④ 内容管理、互动审核等列表增加时间维度（列表列 + 检索项）
**现状**：`Content` 已有 `createdAt` 等时间字段，但内容列表页只用于类型定义，未在表格列展示，也未开放按时间检索/筛选。互动审核（UGC 审核）列表同理。
**方案**：
  - 内容管理列表：新增"创建时间/发布时间"列，筛选区增加时间范围选择；
  - 互动审核（评论/投稿审核）列表：同样增加时间列 + 时间范围筛选。
**涉及文件**：`src/app/[locale]/(admin)/admin/(panel)/content/page.tsx`、`.../ugc/page.tsx`，及对应的 `src/app/api/admin/*` 列表查询接口（加 `createdAt` 范围过滤参数）。
**工作量**：S～M。
