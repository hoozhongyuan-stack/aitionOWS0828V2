# AitionOWS V4.6.7 升级计划(后台列表一致性 + 用户资料展示)

> 分支 main(基于 v4.6.6) · 零迁移 · 预计 1 天
> 范围:三件事 —— ① 列表页宽度统一 ② 注册用户列表展示已填写资料 ③ 互动审核默认筛选
> 说明:2026-09-13 用户确认后已实施(见文末「实施结果」)

---

## 一、问题确认(证据)

### 1. 列表页宽度不统一(结构已定位)

后台 14 个"以表格为主体"的页面里,**9 个套了 `mx-auto w-full max-w-6xl`(上限 1152px),5 个没有上限(能用满内容区)**:

| 有 1152px 上限(9) | 无上限(5) |
|---|---|
| 注册用户 `users`、互动审核 `ugc`、表单管理 `forms`、文件 `media`、栏目 `categories`、导航 `navigation`、语言 `i18n`、SEO `seo`、备份 `backup` | 内容 `content`、商品管理 `products`、订单管理 `orders`、访问明细 `geo-events`、操作日志 `admin-logs` |

实测(1440px 视口,同一台机器连续测量):

| 页面 | 内容区 | 页面容器 | 表格实际宽度 |
|---|---|---|---|
| 内容(基准) | 1216 | 1168(无上限) | 1168 |
| 注册用户 | 1216 | **1152** | 1152 |
| 表单管理 | 1216 | **1152** | 1152 |
| 互动审核 | 1216 | **1152** | **1102**(表格在 Card 内,padding 再吃掉 48px) |

**为什么 1440 视口下只差 16px 却感觉"太窄"**:`max-w-6xl` 是**硬上限**,窗口越宽差距越大 —— 1920 宽时差约 480px,2560 宽时差约 1100px。大屏上三页会被"锁"在 1152px,而内容/商品页铺满,观感差异明显。互动审核还额外少了 50px(表格未填满容器),更显窄。

### 2. 注册用户列表不显示已填写的资料(保存没问题,展示缺列)

**先排除保存故障** —— 生产库实测,用户在后台填的 4 个字段全部落库:

```
id=4 nickname=Leo  companyName=深圳微云仓信息技术有限公司  country=中国  province=广东  city=深圳
```

保存链路也正常:接口 `PATCH /api/admin/users` 的 zod schema 完整接收 4 字段,服务层返回后页面 `saveProfile()` 会调 `load()` 重新拉列表。

**真正的问题在展示**:列表 9 列里**只有「公司名称」**用了资料字段,`country/province/city` 三个字段**在列表里完全没有位置**(仅编辑弹窗内可见)。即"填了 4 项,回到列表只看得见 1 项"。

同类排查(是否有别的列表也漏展示已填字段):

| 页面 | 结论 |
|---|---|
| 表单管理 → 数据 | ✅ 按表单 schema **动态生成列**,填写内容完整展示 |
| 投稿审核(互动审核 tab2) | ✅ 标题/投稿人/栏目/时间/状态齐全 |
| 注册用户 | ❌ 只有公司名称,地区三字段无处展示 ← **本次要修** |

### 3. 互动审核默认筛选把已处理的数据藏起来

现状:`status` 初值 `"PENDING"`(待审核),下拉里**有**「全部」选项但默认不选中。

生产实况:全站唯一一条评论 `where are U？`(contentId=45)状态是 **APPROVED**,用户进入互动审核 → 默认筛选"待审核" → 看到 **"共 0 条 / 暂无待审核评论"**,容易被误读成"数据没进来"。投稿审核 tab 的初值同样是 `"PENDING"`。

对照:内容列表的默认状态筛选是**「全部状态」**,两处口径不一致。

## 二、修改方案

### ① 列表页宽度统一(去掉硬上限)

**规则**:主体是**表格列表**的页面一律不限宽(用满内容区);主体是**表单/配置**的页面保留 `max-w-6xl`(宽了反而难读)。

- **必改(用户点名)**:`users`、`ugc`、`forms` → 去掉 `max-w-6xl` 容器上限
- **建议同步(同属表格列表,避免下次又发现不一致)**:`media`、`categories`、`navigation`、`i18n`、`seo`、`backup`
  - 其中 `i18n`(命名空间/键两列内容都很长)、`seo`(标题列长)加宽收益明确;`backup` 可保留上限,由你定
- **保持上限**:`theme`、`settings`、`brand`、`security`、`dashboard`(配置表单)
- **顺带修**:互动审核表格在 Card 内 padding 后只有 1102px(容器 1152)→ 页面变宽后随之解决;`companyName` 等单元格的 `max-w-*` 截断保留,但补 `title` 悬浮显示全文

### ② 注册用户列表展示「国家/省/市」

推荐 **A**:把「公司名称」列改成两行「资料」列(与「用户」列两行结构一致,不增加列数):

```
深圳微云仓信息技术有限公司
中国 · 广东 · 深圳          ← 小字灰色,缺项自动跳过,全空显示 -
```

备选 **B**:独立新增「地区」列(显示 `中国 · 广东 · 深圳`),便于横向扫读;缺点是用户表列数已达 9,再加会挤。
备选 **C**:只在编辑弹窗与悬浮提示里看 —— 不满足"列表里也要能看到",不建议。

其他细节:地区文本超长时 `truncate` + `title` 悬浮;`国家/省/市` 全空时显示 `-`(与现有空值风格一致)。

可选(不在本次):把 `country/province/city` 纳入列表搜索(现在只支持 邮箱/昵称 与 公司名称 两个搜索框)。

### ③ 互动审核默认筛选

推荐 **A**:默认改为**「全部」**,与内容列表的「全部状态」口径一致;待办感由状态徽标承担(待审核=红色 destructive 徽标,已通过/已驳回各有色),空态文案改为区分"确实没有数据"与"当前筛选下没有数据"。

备选 **B**:保持默认「待审核」,但在结果为 0 且存在其他状态数据时,空态提示「暂无待审核;已通过 3 条 / 已驳回 1 条 → 查看全部」(工作队列语义更强,但要额外查一次计数)。

备选 **C**:不改,靠使用者自己切「全部」。

## 三、验证要点

1. 三个页面在 1440 / 1920 两个视口下,容器宽度与内容页一致;表格铺满容器;横向不出现滚动条
2. 浅色/深色两种系统外观下无错位;`表格 + 筛选栏 + 分页`三者对齐
3. 注册用户:填入 公司名称 + 国家/省/市 后保存 → 列表**立即**显示新值(不刷新页面);只填部分字段时缺项不显示占位符;超长文本截断且悬浮可见全文
4. 互动审核:默认进入即看到全部评论/投稿,状态徽标正确;筛选切回「待审核」时只看到待审条目
5. 回归:列表页涉及的批量选择、分页、搜索、批量操作(内容/栏目/导航/用户/投稿/订单)不受宽度改动影响 —— 这些功能此前都验证过,属回归项
6. 门禁:`npx tsc --noEmit`、`npm run lint`、`npx vitest run`(现有 232 用例)、`npx next build`;如需锁行为,补 1~2 条断言(例如用户列表行渲染包含地区字段)

## 附录:本次范围外的相关发现(待你定,均不写入代码)

1. **腾讯元宝抓取口径**:元宝没有独立爬虫 UA,其公网抓取走 `Sogou web spider`,而搜狗在本项目口径里属「传统搜索」分区 → 元宝来抓会显示成"搜狗(传统搜索)"。元宝**引荐已支持**(`yuanbao.tencent.com` 在白名单,本地实测可记录)。三个选项:A 保持现状(推荐)/ B 把搜狗在 AI 分区镜像一份(会重复计数)/ C 仅在文案上标注「搜狗(腾讯元宝内容源)」。
2. **AI 引荐白名单精度**:匹配用主机名子串,`chat.deepseek.com` 能命中,但 `deepseek.com`、`www.deepseek.com` 会漏记;同类还有 `doubao.com` 之外的可能域。建议扩成"主域名兜底匹配",但会略微提高误判率(需权衡)。
3. **WorkBuddy 的可见性上限**:它是桌面 AI 客户端(接我们的 MCP),没有公网爬虫 → 永远不会出现在「抓取」分区;它通过 MCP 调用接口的记录按设计也不进 GEO(`/api` 路径被排除)。若想量化它带来的价值,建议改为统计 MCP 调用次数(另立项)。

## 五、实施结果(2026-09-13,用户确认后执行)

**用户裁定的选项**:① 宽度 = 必改 3 页 + 建议同步 6 页(共 9 页全部去上限);② 用户资料 = 方案 A 两行「资料」列;③ 互动审核 = 方案 A 默认「全部」;④ 追加:AI 引荐白名单扩「主域名兜底匹配」。

| 项 | 实施 | 实测 |
|---|---|---|
| ① 宽度统一 | 9 个表格页去掉 `mx-auto max-w-6xl`;配置表单页保留(theme/settings/brand/security/dashboard/banners) | 注册用户容器 1152→**1168**(与内容页一致)、表格 1152→1168;表单管理 1152→1168;互动审核表格 1102→1118(填满 Card) |
| ② 资料列 | 「公司名称」列改两行「资料」列:公司名称 + 地区小字(缺项跳过,空值 `-`,两行带 `title`) | 行内容实测 `AiTion 测试科技有限公司` / `中国 · 广东省 · 深圳市` 两行 |
| ③ 互动审核默认 | 评论审核与投稿审核默认 `ALL`,空态区分"没有数据/当前筛选下没有" | 默认「全部」,显示 2 条已通过评论(改前默认待审核为 0 条) |
| ④ 引荐兜底 | `AI_REFERRERS` 由 `{match: 子串}` 改 `{name, domains[]}` + 主机名边界匹配(host === 域 或 以 `.域` 结尾);补齐 DeepSeek 根域、moonshot.cn、qwen.ai、z.ai、xfyun.cn、chat.openai.com、x.ai 等(DoH 核实);文心仍只认子域以保互斥 | 9 条新断言全绿:`www.deepseek.com`/`chat.deepseek.com`→DeepSeek、`m.doubao.com`→豆包、`www.tencent.com`→null、`deepseek.com.evil.com`→null、`www.baidu.com` 仍→百度搜索(传统搜索)、裸主机 `chat.deepseek.com`→DeepSeek |

门禁:233 测试全绿、lint 0 warning、`tsc --noEmit` 清零、`next build` 通过。

**附录三项的处置**:第 2 项(白名单精度)本轮已实施;第 1 项(元宝走搜狗口径)与第 3 项(WorkBuddy 走 MCP、不进 GEO)仍待决策,本次未动。
