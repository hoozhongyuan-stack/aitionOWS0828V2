# V4.8.4 升级计划:多语言封面图(英文封面)

> 状态:**待用户确认,未动代码**
> 需求:文章封面图支持上传英文版本;英文页没传英文封面时,回退使用中文封面。
> 用户已拍板:① 全内容类型统一加(封面字段是 Content 共用的,商品同样受益);② UGC 投稿一期不支持传英文封面(WorkBuddy MCP 推文同理)。

---

## 1. 现状与关键事实

- 站点固定两个语言:`zh-CN` / `en`(`src/i18n/routing.ts:11`)。
- 封面存在内容主表 `Content.coverUrl`,**全语言共用一张**(`prisma/schema.prisma:151`);英文页的详情大图、列表卡片、og:image 现在显示的都是中文封面。
- `ContentTranslation` 已按语言维护 title/summary/body/TDK/specs(`prisma/schema.prisma:186`),**没有封面列**——本方案即在此表补一列。
- 项目已有完全同构的先例:**V3.1 每语言规格参数**(翻译表按语言维护 + 主表兜底 + deleteMany/recreate 前快照回填,`src/server/content/index.ts:318-358`)。封面照搬这套语义。
- 上传管道零新增:后台图片上传已经自动做 WebP 显示版 + JPG og 伴生 + MediaAsset 登记(V4.7.4),英文封面走同一入口。

## 2. 方案设计

### 2.1 数据模型与迁移

- `ContentTranslation` 新增 `coverUrl String?`。
- 迁移:`ALTER TABLE "ContentTranslation" ADD COLUMN "coverUrl" TEXT;`——SQLite 秒级、无损,存量行全 NULL = **全部回退主表现状,存量内容零影响、零回填**。
- 语义约定:**主表 `coverUrl` = 默认/中文封面(兜底图)**;`ContentTranslation.coverUrl` = 该语言专属封面(现状只有英文 Tab 会暴露此字段)。中文页永远用主表封面,行为不变。

### 2.2 写入语义(三态矩阵,与 specs 完全同款)

`saveContent`(`src/server/content/index.ts:361`)的 `translations[].coverUrl`:

| 传入值 | 语义 |
|---|---|
| `undefined`(缺省) | 保留该语言既有值(deleteMany+recreate 前快照回填) |
| `null` | 清空(写 NULL,即回退主封面) |
| 字符串 | 写入(空串归一为 NULL) |

- 快照 Map 从「仅 specs」扩为「specs + coverUrl」(`index.ts:453-460` 一处改动)。
- 该语义天然保护所有"不认识这个字段"的调用方:
  - **UGC 投稿**(`src/server/ugc/index.ts:320` 直写主表封面、直建翻译行不带封面列)→ 翻译行封面 NULL,回退主封面,行为不变;
  - **WorkBuddy MCP 推文**(`tools/workbuddy-mcp/index.js:229` 未传语言用 `{...prev}` 原样回传,经 GET /api/admin/contents 拿到含封面的翻译行)→ 字段在 zod 声明后原样往返,**零改动自动兼容**。
- 边界语义(写进后台提示文案):英文 Tab **标题清空**时该翻译行不落库(`withTitle` 过滤),英文封面随行失效、回退主封面——标题是翻译行存在的意义,封面依附于行。

### 2.3 读路径回退链

统一回退表达式:`该语言 translation.coverUrl || 主表 coverUrl`。改动收口在服务层出口,前台组件(`content-card.tsx`、`layout-presets.tsx` 等)**零改动**:

| 出口 | 位置 | 改动 |
|---|---|---|
| 列表卡片(栏目页/首页楼层/最新内容) | `shapeCard`(`index.ts:988`) | 翻译行类型加 coverUrl,出口处解析;调用方 select 补字段(`index.ts:691`) |
| 文章详情(大图 + og:image 同源) | `getPublishedBySlug`(`index.ts:784`) | 返回解析后的 coverUrl,`article/[slug]/page.tsx:58/118/154` 自动跟随 |
| 站内搜索卡片 | `searchPublished`(`index.ts:904/923`) | select 补字段 + 解析 |
| 商品详情(og:image 兜底链 `gallery[0] ?? coverUrl`) | `getProductBySlug`(`product.ts:145`) | coverUrl 解析;**图集 gallery 本身跨语言,一期不动** |
| 账号页收藏列表(用户侧) | `listMyFavorites`(`ugc/favorite.ts:154`) | 同款解析(英文用户收藏夹看到英文封面) |
| 后台各列表(内容/商品/投稿审核) | `listContentsAdmin` 等 | **不改**,后台始终展示主表兜底封面本体 |

- 订单明细缩略图是下单时刻的快照列(`OrderItem.coverUrl`),不在本需求范围,不动。
- llms.txt / sitemap 不含封面字段,不涉及;Banner(首页轮播)是独立表,不涉及。

### 2.4 后台编辑器(`content/edit/[id]/page.tsx`)

- 现有「封面图」字段(456 行)label 改为**「封面图(中文/默认)」**,hint 补充「英文页未上传专属封面时使用此图」。
- 其正下方新增**「英文封面(可选)」UploadField**(同一 MediaPicker 入口,素材库/本地上传双 Tab、压缩伴生全自动),绑定 `trans["en"]` 状态;仅当启用语言含 `en` 时渲染。
- `Translation` 接口与 `emptyTranslation` 补 `coverUrl` 字段;加载回显 `t.coverUrl ?? ""`;保存时 translations 全量往返带 `coverUrl: t.coverUrl || null`(307-316 行一处)。
- 中文 Tab 不出现封面字段(主表即中文封面,避免两处来源)。

### 2.5 API 与校验

- `src/app/api/admin/contents/route.ts` zod `translations[]` 补 `coverUrl: z.string().nullable().optional()`,**注释写明三态语义**——此处是 zod 静默剥除历史事故高发区(route 内已有两起事故注释),必须声明 + API 层回归测试锁死。

### 2.6 og:image / 分享

- 英文页 og:image 自动用英文封面(经 2.3 解析后的详情返回值);`pickShareImage` 的 JPG 伴生检查逻辑不变——上传管道已无条件生成伴生 JPG,英文封面同样享受(微信卡片兼容性不受影响)。

## 3. 一期明确不做

- UGC 投稿表单不出现英文封面上传(自动享受回退,不会坏);
- WorkBuddy MCP `push_article` 不加封面参数(自动兼容);
- 商品图集 gallery 的多语言(封面≠图集,如后续有需求另立方案);
- 更多语言(现仅 zh-CN/en;存储层按翻译表设计,未来加语言只改编辑器 UI)。

## 5. 测试计划

1. **写入三态**:translations[].coverUrl 缺省=保留既有 / null=清空 / 字符串=写入;快照回填不被 deleteMany 抹掉(仿 V3.1 specs 用例)。
2. **读路径回退**:英文翻译行有封面 → 详情/列表卡片/搜索/商品详情返回英文封面;无 → 回退主封面;中文页任何情况都用主封面。
3. **zod 声明**:带 coverUrl 的 translations PUT 通过且落库(防静默剥除事故)。
4. **MCP 兼容**:模拟 push_article 的 `{...prev}` 往返,英文封面不丢。
5. **存量兼容**:无翻译封面的内容,所有出口返回值与改动前一致(现状快照)。
6. 全量既有测试(426 用例基线)+ `next build` 门禁。

## 6. 风险与回归重点

- **deleteMany+recreate 快照窗口**:与 specs 同款已知窗口(单编辑者场景已评审接受),不新增风险面。
- **zod 静默剥除**:最高优先回归项(用例 3 锁死)。
- **middleware / 上传管道**:本次不触碰,无需专项回归;后台编辑器保存流程照常全量回归(保存/定时/商品字段不回归损坏)。

## 7. 部署与回滚

- 标准流程:本机构建镜像 save/load → 服务器停 app 容器→load→起(下线约 6 分钟)→ 备份 `pre-v484-<时间戳>`(db 三件套一起)。
- 迁移 `ADD COLUMN` 在启动时自动执行,秒级无损;**回滚 = 换回上一镜像即可**(新列残留无害,旧代码不读它)。
- 上线后照例拷 db 三件套回本地比对行数。
