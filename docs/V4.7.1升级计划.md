## 一、问题确认(证据)

### 1. PC 端图片比正文宽 —— 是 V4.7.0「媒体出血」的副作用

用户截图与实测一致:正文从 x≈361 起、图片从 x≈194 起,两边各多出约 167px。生产实测(1440 视口):

| 元素 | 实测宽度 |
|---|---|
| `<main>` 正文容器 | 840px |
| 正文文本 / 导语块 | 810px |
| 封面图、正文内图片 | **1080px**(`xl:-mx-36` 负边距出血) |

根因:V4.7.0 为文章详情页加了"正文窄、媒体宽"的杂志版式设计(`.rich-content--bleed` + 封面 `xl:-mx-36`),与用户期望的"图片和文字一样宽"相反。

### 2. 朋友圈无缩略图、聊天有 —— 分享图尺寸不达标(且两次分享的不是同一页面)

**先纠正一条此前的错误结论**:我曾记录"微信聊天发外链不渲染 OG(平台策略)"——用户截图显示**聊天卡片完整渲染了标题+摘要+缩略图**,该结论作废。

**证据链(全部实测)**:

| 项 | 实测结果 |
|---|---|
| 朋友圈那张卡片的标题 | 「数字中圆·酒业数智增长观察站 \| 数字中圆」= **首页的 `<title>`** → 那次分享的是**首页** |
| 聊天那张卡片的标题 | 「酒业新观察:酒类流通的主导逻辑…」→ 分享的是**文章** |
| 首页 og:image | `192f697a….png` = **600×180 LOGO**(首页 Banner 数为 0,兜底链 `首张轮播图 → 品牌 LOGO` 落到 LOGO) |
| 文章封面(抽查 6 篇) | 全部 **1200×675 PNG**,合规 |

**根因**:微信要求 og:image **≥300×300**(朋友圈大图推荐 1200×630)、HTTPS 绝对地址、JPG/PNG、可直连不跳转、且必须写在服务端初始 HTML 里(我们是 SSR ✓)。**首页那张 LOGO 高只有 180,不达标 → 朋友圈回退成默认链接图标**;文章封面 1200×675 达标 → 聊天卡片正常。

**另外发现一个缺口**:站点输出 `og:image` 但**没有 `og:image:width` / `og:image:height`**。社交爬虫靠这两个值决定卡片版式,显式声明可减少"拿不准尺寸就不给图"的情况。

兜底链现状(`src/lib/seo/open-graph.ts`):`imagePath(首页=首张轮播图) → brand.logoUrl → 省略`。**没有任何尺寸校验**。

### 3. 公众号域名配置 —— 校验文件未上传,且 apex 会跳转

| 项 | 实测 |
|---|---|
| `https://www.aition.xin/MP_verify_15IT1sxGE1qoTFQx.txt` | **404**(文件未上传) |
| `https://aition.xin/任意路径` | **301 → www.aition.xin**(Caddy 里 `aition.xin { redir https://www.aition.xin{uri} permanent }`) |
| 既有先例 `public/fejKunK1BB.txt`(上次开放平台网站应用的校验文件) | `www` 下 **200**、内容正确;`aition.xin` 下 **301** |

校验文件本体:`~/Downloads/MP_verify_15IT1sxGE1qoTFQx.txt`,16 字节、**无换行**、内容 `15IT1sxGE1qoTFQx`。

**⚠️ 关键取舍**:用户当前在微信后台填的是 **`aition.xin`**(apex)。微信校验是去**所填域名**的根路径抓文件,而 apex 对**所有路径**返回 301 跳转到 www —— 既有校验文件在 apex 下也是 301,说明这是**长期存在的跳转**,不是偶发。因此填 apex 极可能校验失败,而**本月的修改次数只剩 5 次**。

### 4. 三个目标的能力边界(这是本次最需要你看清的部分)

用户希望实现:菜单挂链接 / 微信登录 / 微信内自定义分享。经查,三者在**个人订阅号**上的可行性与替代路径如下:

| 目标 | 个人订阅号能否直接实现 | 说明与替代路径 |
|---|---|---|
| **自定义菜单挂外链** | ❌ 不能 | 未认证订阅号的菜单不支持「跳转网页」填任意外链,只能跳公众号内图文/历史消息。**替代:图文消息底部的「阅读原文」**(官方文档口径下未认证订阅号唯一可用的外链方式) |
| **微信登录(网页授权 OAuth)** | ❌ 不能 | 网页授权(OAuth)**仅认证服务号支持**;订阅号后台连「网页授权域名」入口都没有(用户截图里确实只有「JS接口安全域名」+「消息推送」,与此一致)。**正确路径:微信开放平台「网站应用」扫码登录**(独立体系)——我们此前已配置好(`public/fejKunK1BB.txt` 就是它的校验文件),**卡在开放平台应用审核上线** |
| **微信内自定义分享卡片** | ❌ 不能 | JS-SDK 分享接口(`updateAppMessageShareData`/`updateTimelineShareData`)要求**认证服务号或已认证的非个人订阅号**,个人订阅号无权限。**替代:只能靠 og:image**(即问题 2 的方案),这也是目前唯一能让分享卡片好看的路子 |

**结论**:JS 接口安全域名即使配置成功,**当前也换不来上面任何一个能力**。配它的唯一价值是"为将来升级账号类型(或开放平台应用通过后)预留基础"。是否要配由你定 —— 上传一个静态文件成本极低,且已经有先例(`fejKunK1BB.txt`),我建议顺手配上、但不指望它立刻带来功能。

## 二、修改方案

### A. 图片与正文对齐(问题 1,推荐方案 A)

- 删除 `src/styles/globals.css` 中的 `.rich-content--bleed` 规则块(仅文章详情页生效的媒体出血)
- 删除文章详情页封面外层的 `xl:-mx-36`,并去掉正文容器上的 `rich-content--bleed` 类
- 结果:正文 840px、封面与正文内图片/视频/表格**同为 810px**,全页左对齐一致
- 说明:图片用的是 `max-width` 上限,**不会把小图放大**,不会变形;正文列宽(840px)与 V4.7.0 保持一致,不回退

备选:封面保留出血、只有正文内图片与正文同宽(若你希望封面更抓眼);或把正文列再放宽到 960px(不解决"图比文字宽"的关系,不建议)。

### B. 分享卡片兜底(问题 2,推荐 A)

1. **新增「默认分享图」设置**(品牌信息页):建议上传 1200×630 的横图;og 兜底链改为 `内容封面 → 默认分享图 → 品牌 LOGO`
2. **加尺寸校验**:`MediaAsset` 已存 `width`/`height`,生成 og:image 时候选图**任一边 < 300 就跳过**,继续往下兜底 —— 这样即使某张封面偏小,也不会出现"朋友圈没图"
3. **补 `og:image:width` / `og:image:height`**:让社交爬虫直接知道尺寸,不必下载后再判断
4. 顺带:若候选图 `mime` 是 `image/webp`,提示后台(微信对 WebP 支持不稳定,分享图建议 PNG/JPG)——仅提示,不强制转换

备选(零开发):给首页配一张 1200×630 的轮播图,现有兜底链会自动拿它当 og:image —— 可作为**立即验证**手段。

### C. 公众号校验文件与域名(问题 3,按用户选定的「办法 B」)

1. **把校验文件放进仓库 `public/`**,随镜像发布(与上次开放平台校验文件完全相同的做法):
   - 新增 `public/MP_verify_15IT1sxGE1qoTFQx.txt`(内容 `15IT1sxGE1qoTFQx`,无换行,16 字节)
   - 走已跑通的发布流程:本机构建镜像 → 传输 → `docker load` → `compose up -d --no-build`
2. **微信后台域名改填 `www.aition.xin`**(不要填 apex):这是站点真正提供服务的主机名,校验文件在该域名下可直连返回 200
3. 校验地址(发布后自测):`https://www.aition.xin/MP_verify_15IT1sxGE1qoTFQx.txt` → 200、内容为 `15IT1sxGE1qoTFQx`
4. **80 端口预案**:微信校验历史上走 HTTP(80),我们的 80 会 308 跳 HTTPS。多数情况可跟随跳转;若第一次校验失败,再给 80 端口加一条该路径的直答规则(Caddy)后重试
5. **付费注意**:本月仅剩 5 次域名修改机会,务必先在浏览器自测通过再点"确定"

> 如果将来确实需要 apex(`aition.xin`)也通过校验,需要在 Caddy 的 apex 站点块里为该校验路径单独加"直答、不跳转"的规则 —— 可作为后续可选项。

## 附:结论所依据的官方口径与来源

- 未认证订阅号菜单不支持跳转外链、只能跳公众号内图文(替代:阅读原文):微信开放社区官方回复口径
- 网页授权(OAuth)仅认证服务号支持(错误码 10005「没有 scope 权限」的常见原因就是用了订阅号)
- JS-SDK 分享接口(updateAppMessageShareData/updateTimelineShareData)需认证服务号或已认证的非个人订阅号
- 微信自 2017 年起停用「自动抓取页面第一张图」作为分享缩略图;og:image 需 ≥300×300、HTTPS 绝对地址、JPG/PNG;同一 URL 的 og 数据缓存最长 24 小时
