# AitionOWS V4.7.3 升级计划(对外信任信号:llms.txt 自述 + 结构化数据 + 地址一致性)

> 分支 main(基于 v4.7.2) · 零迁移 · 预计 0.5 天
> 背景:用户在国产 AI 里搜索自家站点,被判定「没有备案」「是个人的,不可信」。实测发现**问题不在备案**:
> 站点页脚的信任信号自相矛盾(玩笑地址 + 模板产品署名),而 AI 恰好就是靠这些页面证据做判断。
> 范围:① 修正代码默认值(模板级缺陷) ② 地址单一事实来源 ③ llms.txt 自述段 ④ 结构化数据补 identifier/description/sameAs ⑤ 生产数据修正

---

## 一、问题确认(生产实测证据)

### 1. 页脚:玩笑地址 + 模板产品署名(最伤的两处)

```
页脚实测文本: … 18688720565 leohoo@petalmail.com
              银河系·地球村·深圳市·龙岗区·大不列颠·小布什·耶路撒冷·911号
              联系微信 公众号 © 2026 AitionOWS. All rights reserved. 粤ICP备2026086168号-2
```

| 项 | 来源 | 性质 |
|---|---|---|
| 玩笑地址「银河系…耶路撒冷·911号」 | **品牌信息.contactAddress**(数据库**数据**) | 早期全站装修时写入的测试数据,一直留在生产 |
| 版权署名「© 2026 **AitionOWS**」 | **代码默认值** `BRAND_DEFAULTS.copyright` | **模板级缺陷**:凡是没改过该字段的部署,页脚都会显示产品名 |

### 2. 同一页面两处地址**互相矛盾**

| 位置 | 取值 | 来源 |
|---|---|---|
| 页脚 | 银河系·地球村·…耶路撒冷·911号 | 品牌信息.contactAddress |
| 结构化数据 JSON-LD | `addressLocality: 深圳`,`streetAddress: 福田区` | **SEO 设置**.city / .address |

AI 做实体交叉验证时,**同一页面两个地址冲突是最强的"不可信"信号**(比单处缺失更严重)。

### 3. llms.txt 自述是模板套话

```
# 数字中圆
> 数字中圆 企业官网:产品与服务介绍、新闻动态、联系方式。 电话:18688720565。 邮箱:leohoo@petalmail.com。
```
来源:`buildLlmsText()` 里**硬编码**的 `企业官网:产品与服务介绍、新闻动态、联系方式`。这是专门写给 AI 读的文件,却没有主体、定位、服务区域、备案信息。

### 4. 结构化数据缺"我是谁"

`OrganizationJsonLd` 现有字段:`name / url / logo / contactPoint(电话+邮箱) / address / geo / areaServed`。
**缺** `identifier`(备案号)、`description`(一句话定位)、`sameAs`(公众号等外部主页)。

### 5. 备案本身其实是合规的(澄清)

- 页脚备案号是**文本**「粤ICP备2026086168号-2」并**链接到 https://beian.miit.gov.cn/**(工信部认可做法)✅
- 后缀 `-2` 表示同一主体下的第 2 个网站 —— 主体真实存在
- **AI 说"没备案"本质是猜测**:工信部数据不开放抓取、不在模型语料里;而它抓到的页脚又是模板署名 + 玩笑地址 → 顺势给出"个人小站不可信"的先验结论

### 6. 为什么值得改

AI 对"是否可信"的判断**只能依赖页面证据**。当前四类证据(页脚署名、地址、llms.txt 自述、结构化数据)里,两类是错的、一类是空的、一类自相矛盾 —— 等于把"不可信"写在了门口。

## 二、修改方案

### A. 修正代码默认值(模板级,所有部署受益)

1. `BRAND_DEFAULTS.copyright` 由 `© {year} AitionOWS. All rights reserved.` 改为**中性兜底**:
   `© {year} {siteName}`,并让页脚在 `copyright` 为空时用 `© {year} {siteName}` 渲染 → **产品名不再出现在任何客户的页脚**
2. `siteName` 默认值仍是 "AitionOWS"(模板名),属合理默认(部署后由后台改);在品牌信息页给该字段加提示「将出现在页脚署名、分享卡片、结构化数据」
3. 地址类默认值保持为空(现状已为空,不回退);**不预置任何示例地址**,避免再被当成真实数据

### B. 地址的单一事实来源(推荐方案 A)

现状:页脚读**品牌信息.contactAddress**,结构化数据读 **SEO 设置.city/address** —— 两个字段、两套值,极易不一致。

- **方案 A(推荐)**:以**品牌信息.contactAddress 为唯一事实来源**,`OrganizationJsonLd` 的 `streetAddress` 改用它;`addressLocality` 仍取 SEO 设置的 `city`(只保留"城市"这一粒度)。理由:地址属于**主体信息**,归品牌;SEO 设置里那份是 GEO 地理信息的半成品。
- 方案 B:保留两个字段,但代码内做兜底(一方为空时取另一方)+ 后台两处互相提示
- 方案 C:只改数据不改代码(后台把两处都填成同一地址)

无论选哪个,SEO 设置页与品牌信息页都要加一句提示(「与品牌信息中的地址保持一致,页脚与结构化数据会同时使用」),避免下次又填出两个版本。

### C. llms.txt 自述段增强

把硬编码套话换成**结构化自述**,数据全部来自现有后台字段:

```
# {siteName}
> {一句话定位}                          ← 新增字段(见下)
运营主体:{主体名称} · 服务区域:{SEO.areaServed} · 联系方式:{电话} / {邮箱}
备案信息:{ICP 备案号}(查询:https://beian.miit.gov.cn/)
内容范围:{主要栏目名}(酒业洞察/解决方案/案例…)
```

- 新增**「站点一句话定位」**字段(放品牌信息,约 60 字):**一处填写、两处使用**(llms.txt 自述 + JSON-LD `description`)—— 这也是 AI 最需要的"你是谁、做什么"
- 备案信息由「品牌信息.icp」提供;为空则整行不输出(不影响非备案场景)

### D. 结构化数据增强(OrganizationJsonLd)

| 字段 | 取值来源 | 说明 |
|---|---|---|
| `identifier` | 品牌信息.icp | 备案号作为通用标识(schema.org 无 ICP 专用属性) |
| `description` | 新增「站点一句话定位」 | 缺失时回落 SEO description |
| `sameAs` | 品牌信息.socials[].url | 公众号/其他平台主页,给 AI 实体锚点(可选、有空值即跳过) |
| `address.streetAddress` | 品牌信息.contactAddress(方案 A) | 与页脚一致 |
| `foundingDate` | 可选,先不做 | 需要用户提供成立时间 |

### E. 生产数据修正(本次必须一起做,否则改了代码页面照样错)

| 字段 | 现在 | 改成 |
|---|---|---|
| 品牌信息.contactAddress | 银河系·地球村·…耶路撒冷·911号 | **真实办公/经营地址**(由你提供) |
| 品牌信息.copyright | © 2026 AitionOWS. All rights reserved. | 主体署名,建议 `© 2026 {主体名} · 粤ICP备2026086168号` |
| SEO 设置.city/address | 深圳 / 福田区 | 与上一行地址保持一致(方案 A 下 address 可作废) |
| 品牌信息.一句话定位 | (无此字段) | 一句业务定位(由你提供) |
| 关于页(/c/about) | 无主体/团队/备案信息 | 补运营主体、业务范围、服务对象、联系方式、备案号 |

> 这五项里,前四项是**后台配置**,第五项是**内容**。建议我出「填哪些字段、填什么」的清单,由你在后台确认保存 —— 涉及主体信息,你本人确认更稳妥;也可由我代改(给你 diff 复核)。

## 三、验证要点

1. **页脚**:不再出现 `AitionOWS` 字样与玩笑地址;备案号仍是文本 + 工信部链接;版权署名主体正确
2. **一致性**:页脚地址与 JSON-LD `streetAddress` **完全相同**(抓取两处字符串比对)
3. **结构化数据**:`identifier` / `description` / `sameAs` / `address` 均存在且取值正确(JSON 解析断言);仍为合法 JSON-LD,Google 富媒体测试无报错
4. **llms.txt**:包含主体、定位、服务区域、联系方式、备案号;仍是合法 Markdown 且结构未破坏(现有 llms.txt 测试全绿)
5. **后台**:新增字段有提示文案;非备案站点(icp 为空)不输出备案行、不报错
6. **回归**:OG 标签、文章 JSON-LD、页脚社交链接、多语言(en 站点的 llms.txt 与结构化数据)不受影响
7. **门禁**:`tsc --noEmit`、`lint`、`vitest run`(现有 276 用例)、`next build`
