## P0 缺陷修复 + 首次运行基线

**目标**:把"从未跑过"的脚手架变成"验证可运行"的基线,消除审计发现的全部严重缺陷。

**内容**
1. 修复 3 个严重缺陷:
   - schema.prisma 的 6 个 enum → `String` 字段 + `src/types` 常量 + zod 校验(SQLite 不支持 enum);
   - `DATABASE_URL` 改为相对 schema 目录的正确路径(`file:../data/app.db`),同步改 compose;
   - seed 的 `upsertSettings` 改为 `update: {}`(已存在配置不覆盖)。
2. 处理 3 个中等问题:standalone 与启动方式二选一(倾向:保留 standalone + `node server.js`、精简镜像)、db.ts 启动执行 `PRAGMA journal_mode=WAL`、next.config 注释矛盾修正。
3. `git init` + `.gitignore` 生效确认 + 首次提交;`npm install` 生成 lockfile。
4. `prisma db push` + `db seed` + `npm run dev` + `npm run build` 全通。

**质量审查(门禁)**
- [ ] `npx prisma validate` / `db push` 零报错;`data/app.db` 生成在项目根 data/ 下且 WAL 生效
- [ ] 重复执行 seed 两次,手工改一条 Setting 后再 seed,**配置不被覆盖**
- [ ] `npm run dev`:`/zh-CN`、`/en`、`/zh-CN/admin` 三页正常渲染,无 console 报错
- [ ] `npm run build` 零错误;git 有首次提交

## P1 基础设施层(配置管线 / 认证 / 存储)

**目标**:打通产品最核心的承诺——**后台改配置 → 前台即时生效、无需重启**;建立管理员认证与本地文件存储两大地基。

**内容**
1. **配置管线**:`server/setting`(读写 Setting + JSON 序列化)+ `lib/config`(内存缓存 + `revalidateTag` 失效);根布局接入 DB 主题注入(CSS 变量内联 `<style>`)。
2. **管理员认证(自研 JWT)**:`lib/auth`(bcrypt 校验 + jose 签发 httpOnly cookie);admin 登录页;`(admin)/admin/layout.tsx` 统一鉴权;middleware 轻量 cookie 存在性检查。
3. **本地存储**:`lib/storage`(路径安全/写 uploads/)+ 上传 API + sharp 压缩 + `MediaAsset` 登记 + `/uploads` 静态服务路由;上传限制读 `Setting(upload)`。
4. **shadcn/ui 初始化**:生成本项目所需基础组件集(button/input/form/table/dialog/select/tabs 等)。
5. **API 骨架**:`app/api` 目录建立,统一响应格式、错误处理、zod 校验管道。

**质量审查(门禁)**
- [ ] 后台改主色 → 前台刷新立即变色,**进程不重启**(核心验收,录屏级验证)
- [ ] 未登录访问 /admin 一律跳登录页;错误密码不可登录;cookie 为 httpOnly
- [ ] 上传超限文件被拒;图片压缩生效;文件落在 uploads/ 且 MediaAsset 有记录;路径穿越攻击(`../`)被拦截
- [ ] 页面/Route Handler 无一处直接 import prisma(grep 检查)

## P2 主题 / 品牌 / 多语言后台(需求 4.2、4.3)

**目标**:全站视觉与站点信息 100% 后台可视化,零硬编码。

**内容**
1. 后台「主题设置」:调色板(主/辅/文字/按钮/背景色)、字体(全站/标题/正文 + 字号/行高)、暗色模式。
2. 后台「品牌设置」:名称/LOGO/ICO/备案号/版权/联系方式/社交账号;**维护模式开关 + 自定义文案**(middleware 拦截前台)。
3. 后台「语言设置」:启用语言勾选、默认语言;前台语言切换按钮;`UiTranslation` DB 覆盖静态文案(DB 优先、文件兜底)。

**质量审查(门禁)**
- [ ] 需求 4.2/4.3 逐条对照通过;所有配置改动即时生效
- [ ] 维护模式开启:前台全被拦到维护页、后台仍可访问;关闭后立即恢复
- [ ] 切换默认语言后,裸域访问落到新默认语言;LOGO/备案号/版权在前台正确渲染

## P3 CMS 内容管理(需求 4.4)

**目标**:完整内容生产链:栏目 → 内容 → 导航 → 前台展示。

**内容**
1. 栏目管理:树形增删改、排序、隐藏、模块类型、外链;导航管理(关联栏目/自定义链接/排序/新窗口)。
2. 内容管理:Tiptap 富文本(图文/视频/表格/链接/列表,图片走本地上传管线);多语言 tab 编辑;草稿/发布/下架/**定时发布**(请求时惰性判定 + 定时器兜底);列表筛选分页。
3. 前台:动态栏目页(按模块类型渲染列表)、内容详情页、导航/页脚渲染。

**质量审查(门禁)**
- [ ] 需求 4.4 逐条对照;富文本输出 HTML 语义干净(无编辑器私有标签垃圾)
- [ ] 定时发布:设定未来时间,到点前不可见、到点后可见
- [ ] 栏目隐藏/排序在前台导航即时反映;删栏目对内容的处理有明确策略(禁删或迁移)
- [ ] 多语言内容缺失某语言时有兜底策略,不出空白页

## P4 SEO / GEO / AI 检索优化(需求 4.1)

**目标**:检索友好度达到可交付标准——这是需求标注的"重点优先"项。

**内容**
1. 单页 TDK:首页/栏目/详情 `generateMetadata` 全覆盖;后台 SeoMeta 编辑;hreflang alternates。
2. GEO 后台配置(城市/地址/经纬度/服务范围/地域关键词)→ 注入 JSON-LD。
3. 结构化数据:Organization / Article / Product / BreadcrumbList;图片 alt 强制渲染、视频语义化标签。
4. sitemap.xml 从已发布内容动态生成(含多语言 alternates);robots.txt 后台可配。

**质量审查(门禁)**
- [ ] Google Rich Results Test / Schema 校验器零错误;view-source 可见完整 SSR HTML
- [ ] 每页 title/description 唯一且来自配置;sitemap 包含全部已发布 URL、不含草稿/下架/待审
- [ ] Lighthouse SEO ≥ 95

## P5 自定义表单获客(需求 4.5)

**目标**:后台可视化建表单,前台场景化收集线索,数据可管理导出。

**内容**
1. 表单构建器:字段类型(输入/单选/多选/下拉/日期/文件)、字段名/必填/提示/校验规则、排序;schema 存 JSON。
2. 前台动态渲染器:按 schema 渲染 + zod 动态校验 + 文件上传接本地存储;表单可关联栏目/页面。
3. 数据管理:查看/筛选/删除/CSV 导出;防重复提交(指纹 + 时间窗)+ 频率限制。

**质量审查(门禁)**
- [ ] 需求 4.5 逐条对照;构建器所改即前台所见
- [ ] 必填/格式校验前后端双重生效(绕过前端直接 POST 也被拦)
- [ ] 同一指纹短时间重复提交被拒;CSV 导出中文不乱码

## P6 用户账号与协议(需求 4.6)

**目标**:前台用户体系 + 协议合规展示,微信登录后台可配。

**内容**
1. 邮箱注册/登录(bcrypt + JWT cookie,与管理员体系隔离);游客模式/强制登录开关(middleware)。
2. 微信 PC 扫码登录:后台配置 AppID/Secret(Secret 加密存储)+ 启用开关;未配置时前台自动隐藏入口;H5 字段仅预留。
3. 协议管理:注册/隐私协议富文本 + 多语言,前台实时展示,注册页强制勾选。
4. 后台用户管理:列表/搜索/禁用/启用(禁用后立即无法登录)。

**质量审查(门禁)**
- [ ] 密码哈希入库(抽查 DB 无明文);登录态 cookie httpOnly + 过期正确
- [ ] 微信未配置→入口隐藏;配置后→扫码流程通(或以 mock 验证回调逻辑)
- [ ] 强制登录开启后游客被拦、关闭后即恢复;禁用用户会话即刻失效

## P7 内容互动 & UGC 审核(需求 4.8)

**目标**:互动数据 + 全链路"先审后发",总开关独立可控。

**内容**
1. 统计展示:阅读量(去重计数)/点赞/转发前台展示;后台手动修改/清零。
2. 点赞(游客 guestKey + 登录 userId 双路防刷)、转发(复制链接 + 计数,多语言 URL)。
3. 评论:登录可评(开关)、提交即 PENDING、后台通过/驳回/删除、前台只显 APPROVED。
4. 投稿:总开关 + 按栏目 `allowSubmit`;前台投稿编辑器(受限 Tiptap);PENDING → 审核 → 上线;我的投稿状态页。
5. 敏感词:词库管理 + 评论/投稿提交时过滤(命中处理策略可配:拒绝/替换)。
6. 功能总开关:点赞/转发/评论/投稿四项独立开关,关闭即前台隐藏入口。

**质量审查(门禁)**
- [ ] **审核红线**:任何路径下未审核 UGC 不出现在前台(含 API 直查、sitemap、搜索)——专项测试
- [ ] 点赞防刷:同一游客指纹重复点赞无效;取消/再点赞计数正确
- [ ] 敏感词命中被处理;四个总开关关闭后前台入口消失且 API 拒绝写入

## P8 内置优化与运维(需求 5)

**目标**:性能、容错、数据安全兜底能力齐备。

**内容**

2. 404/500 文案后台可配;图片懒加载全站确认。
3. 一键备份:DB 文件 + uploads 打包到 backups/,BackupRecord 登记,后台下载/删除。
4. 统计看板:PV/UV(DailyStat 中间件埋点)、表单提交量、内容/评论/用户总量卡片。

**质量审查(门禁)**
- [ ] 缓存命中时改配置仍即时生效(缓存失效链路专项验证)
- [ ] 备份文件可真实还原(恢复演练一次);看板数字与 DB 实测一致

## 贯穿全程的质量制度

1. **每阶段结束**:`tsc --noEmit` + `next lint` + `npm run build` 三件套零错误 → git 提交(约定式 commit,一模块一提交)。
2. **每阶段做代码审查**(/code-review):重点查四条工程铁律——不直连 Prisma、配置不硬编码、UGC 无自动上线、无云 SDK。
3. **需求追踪**:P2 起每阶段验收直接引用需求书条目号,防"做了但不是需求要的"。
4. **文档同步**:架构决策变化实时回写架构设计文档;本计划的门禁勾选状态随进度更新。
