# AitionOWS V3.0 升级计划

> 基于 V3.0 需求头脑风暴整理，并对照当前代码库（Next.js 15 + Prisma/SQLite）核实到具体实现位置。四大需求：商品展示（含二级分类 / GEO / 收藏）、用户资料扩展、邮件模板升级。**微信分享卡片需求已决策舍弃**。此文档为规划稿，待确认后执行开发。

---

## 〇、已确认决策记录

| # | 决策点 | 结论 |
|---|---|---|
| 1 | 商品数据模型 | **复用 Content 体系**（商品 = `moduleType=product` 栏目下的内容），扩展 gallery / specs 字段，不建独立 Product 模型 |
| 2 | 商品询盘 | **纳入 V3**：商品详情页复用 `Content.formId` 机制挂询盘表单 |

## 一、需求①：商品展示（二级分类 / GEO 友好 / 询盘）

### 现状
- `Category.moduleType` 已约定 `product` 类型，`Category.parentId` 已支持树形 → **二级分类零数据模型成本**；
- 但前台无任何商品专属处理：栏目页 `c/[slug]/page.tsx` 对所有 moduleType 渲染同一套 `ContentCard` 通用列表，详情链接固定 `/${locale}/article/${slug}`（`src/components/site/content-card.tsx:26`）；
- `Content` 只有单封面 `coverUrl`，无图集、无参数表，商品信息承载能力不足。

### 方案

**1）数据模型扩展（`prisma/schema.prisma`）**
- `Content` 新增：
  - `gallery String?` —— JSON 字符串，图片路径数组（引用 `MediaAsset`，多语言共享）；
  - `specs String?` —— JSON 字符串，规格参数键值对数组（如 `[{"k":"型号","v":"AX-100"}]`）；
  - `favoriteCount Int @default(0)` —— 收藏数冗余（与 likeCount/shareCount 对称，后台可改/清零）。
- specs/gallery 存主表不分语言：参数（型号/材质/尺寸）通常跨语言通用；若后续需要翻译，再在 `ContentTranslation` 扩展，V3 不做。

**2）商品详情页：新增路由 `/[locale]/product/[slug]`**
- 独立于 `/article/[slug]`，URL 语义化利于 GEO；
- 页面布局：图集查看器（gallery + coverUrl 兜底）→ 规格参数表（specs 渲染为键值表格）→ 富文本正文；
- **询盘**：复用现有 `formId` 机制（文章详情底部渲染关联表单的逻辑已存在），商品详情底部同样渲染，按钮文案用"询盘/获取报价"语境；后台内容编辑页对 product 栏目开放表单关联；
- 链接分流：`ContentCard` 按所属栏目 `moduleType` 生成详情链接（product → `/product/[slug]`，其余 → `/article/[slug]`）。

**3）商品列表模板：栏目页按 moduleType 分流**
- `c/[slug]/page.tsx` 检测栏目（或其父栏目）`moduleType === 'product'` 时渲染商品专属列表：
  - 图卡网格（封面/gallery 首图 + 标题 + 摘要）；
  - **二级分类浏览**：父栏目页顶部渲染子分类页签；子栏目页显示"上级分类 + 兄弟分类"导航；保留现有分页；
  - SSR 保持不变（GEO 前提）。
- 后台内容编辑页（`admin/(panel)/content/edit`）：所选栏目为 product 类型时，动态显示"图集（多图上传，复用 media 组件）+ 规格参数（键值对行编辑器）"区块。

**4）GEO / SEO**
- 新增 `ProductJsonLd`（`src/components/seo/json-ld.tsx`）：`Product` 类型，输出 name / image（绝对 URL）/ description / brand / category / sku（specs 中有型号时）；**不带 offers**（纯展示站，Google 会提示缺 offers 字段，属已知取舍，GEO 引擎主要吃 llms.txt + SSR 正文 + 结构化标题）；
- `llms.txt`（`src/app/llms.txt/route.ts`）：`listForLlms` 已返回全部已发布内容（`src/server/content/index.ts:288`，商品天然包含），改造为按"产品 / 文章"分区输出，产品条目附加参数要点；
- 商品详情单页 TDK 沿用 `ContentTranslation.seoTitle/seoKeywords/seoDesc`；sitemap / hreflang / 图片 alt 均自动继承现有体系。

### 涉及文件
`prisma/schema.prisma`、`src/server/content/index.ts`、`src/components/site/content-card.tsx`、`src/app/[locale]/(site)/c/[slug]/page.tsx`、新增 `src/app/[locale]/(site)/product/[slug]/page.tsx`、`src/components/seo/json-ld.tsx`、`src/app/llms.txt/route.ts`、后台 `content/edit` 页、`messages/*.json`。

**工作量：L**（本次升级最大单项）

## 二、需求②：收藏 + 个人中心

### 现状
- 无任何收藏模型；前台无个人中心，仅有独立的 `/submissions`（我的投稿，72 行小页）；
- 点赞已有成熟范式：`Like` 表（targetType/targetId/userId/guestKey 唯一约束）+ `toggleLike/hasLiked`（`src/server/ugc/index.ts:23,63`）+ `/api/interaction/like`。

### 方案

**1）数据模型：新增 `Favorite` 表**（结构对齐 Like，去掉游客字段——收藏以"个人中心查看"为目的，游客收藏无意义）：
```
model Favorite {
  id         Int      @id @default(autoincrement())
  targetType String   @default("CONTENT")
  targetId   Int
  userId     Int
  createdAt  DateTime @default(now())
  @@unique([targetType, targetId, userId])
  @@index([userId])
}
```

**2）服务层 + API**（`src/server/ugc/index.ts` / 新增 `/api/interaction/favorite`）：
- `toggleFavorite({ targetId, userId })` / `hasFavorited({ targetId, userId })` / `listMyFavorites(userId)`，同步维护 `Content.favoriteCount`；
- 接口强制登录态（区别于点赞支持游客），未登录返回 401。

**3）前端收藏按钮**：
- 文章详情、商品详情互动条（现有 like/share 组件处）增加收藏按钮，登录用户显示已收藏态；未登录点击跳登录页并带回跳（`?redirect=`）；
- 列表卡片暂不放收藏按钮（V3 保持列表轻量）。

**4）个人中心 `/[locale]/account`**：
- 聚合页（Tab）：**我的收藏**（卡片列表，显示文章/商品类型标签——按所属栏目 moduleType 区分，支持取消收藏）、**我的投稿**（迁移现有 submissions 内容：审核状态/正文）、退出登录；
- `/submissions` 保留并 302 到 `/account?tab=submissions`，避免已有入口/外链失效；
- 页头用户菜单（`SiteHeader`）增加"个人中心"入口。

### 涉及文件
`prisma/schema.prisma`、`src/server/ugc/index.ts`、新增 `/api/interaction/favorite`、`src/components/site/interaction-bar`（现有互动组件）、文章/商品详情页、新增 `account/page.tsx`、`submissions/page.tsx`、`SiteHeader`、`messages/*.json`。

**工作量：M**

## 三、需求③：用户资料扩展字段（仅后台维护）

### 现状
- `User` 表仅有 email / passwordHash / nickname / avatarUrl / wechat* / status（`prisma/schema.prisma:226`）；
- 后台用户页（`admin/(panel)/users/page.tsx`）目前只有列表展示 + 禁用/启用，无资料编辑能力。

### 方案
- `User` 新增 4 个可空字段：`companyName / country / province / city`（String?）；
- 后台用户列表增加"编辑资料"弹窗：公司名称、国家、省、市，全部非必填；国家/省市用**自由文本**（不做地区数据字典——模板系统面向不同国家客户，内置全球地区库既重又不准）；
- **隐私约束（验收项）**：前台任何接口（`/api/auth/me`、注册/登录响应等）不得返回这 4 个字段；个人中心不展示、不可编辑；
- 后台用户列表支持按公司名称搜索（顺带提升 B 端客户管理效率，成本极低）。

### 涉及文件
`prisma/schema.prisma`、`admin/(panel)/users/page.tsx`、`/api/admin/users`、`src/server/user/index.ts`。

**工作量：S**

## 四、需求④：邮件模板升级

### 现状
- `src/server/notify/index.ts`：`payload.lines` 纯文本 `join("\n")`，HTML 侧只是逐行转义包 `<p>`——无品牌、无结构、无 CTA。

### 方案
**1）新增模板层 `src/server/notify/template.ts`**：
- 统一品牌 HTML 壳：**头部（LOGO + 站点名，取 brand 配置，绝对 URL）→ 正文区块（支持段落 / 键值对表格 / 高亮框）→ CTA 主按钮 → 页脚（版权 + 备案）**；
- 邮件客户端兼容铁律：表格布局 + 全部内联样式、图片公网绝对 URL、不依赖外部 CSS；
- 主题色取后台主题配置主色，随客户品牌自动换肤；
- `sendMail` 增加 `html` 直传能力，现有 `headerSafe` 头部净化、短超时、静默失败、`void notifyAdmin(...)` fire-and-forget 策略**全部保持不变**。

**2）场景改造**：
| 场景 | 接收方 | 升级点 |
|---|---|---|
| 密码重置 | 用户 | 品牌壳 + 大按钮"重置密码" + 有效期提示；**文案多语言**（随用户当前 locale，zh/en） |
| 表单提交通知 | 管理员 | 结构化展示：表单名、各字段键值表格、来源页面、IP/时间；CTA"去后台处理" |
| 投稿/评论待审提醒 | 管理员 | 品牌壳 + 标题/作者摘要 + "去审核"按钮 |

- 模板文案 zh/en 内置映射；管理员邮件用站点默认语言。

### 涉及文件
新增 `src/server/notify/template.ts`、改造 `src/server/notify/index.ts`、密码重置服务 `src/server/user/password-reset.ts`、表单/UGC 提交链路中的 `notifyAdmin` 调用点、`src/lib/config`（如需新增模板开关）。

**工作量：M**

## 八、验收要点

1. **商品**：product 栏目支持建二级子栏目；列表页签筛选正确；详情页图集/参数表/询盘表单（关联启用表单时）渲染正常；`view-source:` 可见 Product JSON-LD 且无转义错误；llms.txt 含产品分区；商品页 SSR（禁 JS 可见正文）；全链路无价格/购买元素。
2. **收藏**：未登录点击跳登录并回跳；收藏/取消即时生效且 favoriteCount 一致；个人中心收藏列表含文章与商品且可取消；`/submissions` 旧链接可访问。
3. **用户字段**：后台可编辑保存 4 字段；**接口审计确认前台响应不含这些字段**。
4. **邮件**：三类邮件在 Gmail / QQ邮箱 / Outlook 网页版排版正常（图片显示、表格不错位、按钮可点）；SMTP 未配置时静默跳过不影响业务提交。
5. **回归**：文章/评论/投稿/点赞/表单/后台备份全量回归；`prisma migrate` 在存量 V1.2.3 数据库上升级无损。
