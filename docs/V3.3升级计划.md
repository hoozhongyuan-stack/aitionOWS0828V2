## 主线 A · GEO 监测二期（引用探测 + 周报）——【暂缓，后续版本再考虑】

### A1. 引用探测任务

回答「是否被 AI 引用」：预设问题清单 → 定时向各 AI 引擎发起查询 → 快照回答 → 检测品牌/域名是否出现 → 生成差异报告（首次被引用/掉出）。

**引擎适配器（可插拔，后台配置 API Key，无 Key 引擎跳过）**：
| 适配器 | 接口 | 引用来源 |
|---|---|---|
| Perplexity（官方 API，sonar 系列） | ✅ 回答自带引用来源列表（最佳） | API 付费 |
| OpenAI 兼容适配器 | DeepSeek / Kimi(月之暗面) / 智谱 GLM / 豆包(火山方舟) 等国内外 OpenAI 兼容 API，开启联网搜索参数 | 各平台 API 付费 |
| Gemini API | google 检索 grounding | API 付费 |
| 人工登记模式（无 Key 兜底） | 页面列出预设问题+入口链接，管理员手动查询后登记结果 | 免费 |

### A2. 数据模型（一次迁移，纯增量）
```

GeoProbeSnapshot(id, questionId, engine, answerDigest, mentioned   探测快照
                 bool, sourcesJson, probedAt, status)
```

- 快照保留：永久（体量小——每日每问题×引擎 1 行）

### A3. 后台「GEO 监测」页扩展
- 新增「引用探测」Tab：问题清单管理 / 手动立即探测 / 探测历史（按引擎×问题时间线）/ mentioned 变化趋势
- 探测频率：每日 1 次（后台可配）

### A4. GEO 周报邮件

### A5. 验收摘要
- 预设问题 → 立即探测 → 快照含 mentioned 判定与来源
- 每日自动探测（cron 或惰性触发）→ 历史可回看

## 主线 D · 首页楼层配置——【本版本开发，2026-09-07 用户确认纳入】

**背景**：首页现状只有轮播 + 全站最新内容两个区块，没有按栏目配置内容区块的地方（栏目内容只能靠导航进入栏目页）。楼层 = 每层绑定一个栏目，首页一层层往下渲染，层尾带「查看更多 → 该栏目页」。

### D1. 楼层配置模型

后台配置楼层列表，每层可配：

| 配置项 | 说明 |
|---|---|
| 绑定栏目 | 下拉选择 |
| 楼层样式 | `grid3` 三列卡片 / `list` 紧凑列表 / `feature` 首条大图特写+小卡（复用栏目页 magazine 风格） |
| 条数 | 每层取该栏目最新 N 条（默认 6） |
| 层标题 | 默认取栏目名（多语言），可覆盖 |
| 开关+排序 | 显隐、上下移排序 |

### D2. 实现要点

- **零数据库迁移**：楼层存 Setting（group=layout, key=floors）JSON 数组，顺承 V3.2 架构；渲染时跳过已删除栏目（容错）
- 后台「外观设置」加楼层管理（增删改+上下移）；前台按 sort 渲染，每层内容并行查询（层数少，无性能问题）
- 双主题自动适配（data-theme 作用域 + Reveal 滚动显现）；`latest` 区块保留可开关，楼层与它可并存也可替代
- **存量零变化**：未配置楼层 = 现状布局不变

### D3. 影响范围与验收

- 布局服务模块（floors 读写校验）+ 首页渲染分支 + 楼层组件（复用 ContentCard）+ 后台管理 UI + 测试
- 验收：配置两层（不同样式）→ 首页按序渲染 → 「查看更多」指向正确栏目页 → 删除楼层引用的栏目后首页不报错 → 不配置时现状不变

工作量：**S~M**（2~3 天）
