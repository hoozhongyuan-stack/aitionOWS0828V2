# 官网文章规范（aition.art）

站点是中英双语的**产品官网**（售卖"AiTion 企业官网系统"），内容面向外贸企业、独立创作者与有 GEO 需求的企业。文章质量本身就是产品力证明，**宁可少发一篇，不发一篇凑数的**。

---

## 一、写作规范（格式硬约束）

官网正文由富文本白名单渲染，以下规则**不是建议，是会不会被系统剥离的问题**：

| 规则 | 说明 |
|---|---|
| **正文从 `##` 起** | 白名单没有 `h1`——文章标题由 title 字段承担。写了 `#` 会被自动降级为 `##` |
| **只用 `##` / `###`** | `h4` 及更深会被剥壳（文字留下、层级丢失） |
| **不用内联样式** | `<div style="...">`、`<span style>` 全部被剥离；排版靠 Markdown 语义 |
| **可用**：列表、粗体、斜体、行内代码、引用块、表格、链接、图片、视频 | 表格适合做对比（如"优化前后"），引用块适合放结论或要点 |
| **链接自动加 `rel="noopener noreferrer nofollow"`** | 系统行为，无需手写 |
| **不要贴大段代码** | 本站在讲 GEO 方法论时可用短代码片段（如 `llms.txt` 示例），但避免长代码块 |

**结构建议**（一篇 1200–2000 字为宜）：

```
## 开篇结论（2-3 句说清这篇讲什么、对读者有什么用）
## 主体小节 1（一个观点 + 一个例子/数据）
## 主体小节 2
## 落地建议 / 可执行清单
```

**语气**：专业、克制、第二人称（"你可以…"）。不堆形容词，不用"赋能/闭环/抓手"这类词。

## 二、配图规范

图片由你（AI）生成后交给工具上传。尺寸与风格必须对齐官网现有的极光系视觉，否则整站观感会花。

### 封面图（每篇 1 张，必需）

| 项 | 要求 |
|---|---|
| 尺寸 | **1600×900（16:9）** |
| 构图 | **主体居中，四周留安全区**——前台列表会用 `object-cover` 裁剪成 16:9 / 2:1 / 4:3 三种比例，贴边的内容会被切掉 |
| 格式 | webp 或 jpg，**1–2MB**（上限 10MB） |
| 风格 | **深藏青夜空 + 玫瑰红/紫罗兰/青色极光光晕**；几何线条点缀、星点细节；**中心区域压暗**以便叠加白色标题文字时仍可读 |
| 禁止 | 亮白底、卡通插画、写实照片、密集文字（缩略图看不清） |

### 正文插图（0–4 张）

- 尺寸：宽 **1200px** 左右，16:9 或 4:3；宽度会自适应容器，无需精确像素
- 位置：每个 `##` 小节配 1 张，图前后各留一个空行
- 生成后**先用 `upload_image` 拿 URL**，再写进正文：`![图片说明](返回的URL)`
- `alt` 文案要写（利于 GEO）：描述图片实际内容，不是"配图1"

### 视觉提示词模板（可直接用）

```
A deep navy night sky with aurora-like light ribbons in rose red, violet and cyan,
soft glow, subtle geometric constellation lines, star particles, dark vignette in the
center for text overlay, elegant tech aesthetic, minimal, 16:9, high detail
```

## 三、SEO / GEO 写法

推送时这几项能显著影响 AI 引擎如何引用你的内容：

| 字段 | 写法 | 长度 |
|---|---|---|
| `title` | 包含核心关键词、可读不堆砌（如「llms.txt 配置指南：给 AI 爬虫的网站说明书」） | ≤ 40 字 |
| `summary` | 一句话说清"这篇解决什么问题"，会用于卡片与 OG 描述 | 60–120 字 |
| `seoTitle` | 与标题可不同，更偏搜索意图 | ≤ 60 字符 |
| `seoKeywords` | 3–6 个，逗号分隔，**用真实搜索词**而非自造词 | —— |
| `seoDesc` | 补足标题没说到的信息 | ≤ 160 字符 |

**GEO 要点**（本站核心卖点，文章要示范它）：

1. **开头给结论**——AI 引擎更倾向引用"第一段就回答问题"的内容
2. **小标题用疑问句或结论句**——便于被拆成独立引用片段
3. **有可执行的清单**——"三步做法""四个检查项"这类结构化内容被引用的概率最高
4. **中文文章给英文版**——同一篇的中英版本会生成 hreflang 关联，海外引擎各取所需
5. **表格优于长段落**——对比类信息用表格

## 四、推送流程（用 MCP 工具）

工具位于 `aition-content` 连接器（MCP）：

```
1. list_categories                    # 确认投哪个栏目（拿到 categoryId 或名称）
2. list_articles(keyword: "关键词")    # 查重——站内已有同题就别重复发
3. push_article(...)                  # 推送，默认存为「草稿」
4. 把工具回执里的「后台预览链接」给用户看一眼
```

**push_article 参数要点**：

- `categoryId` 或 `categoryName`：二选一（名称中英文皆可）
- `status`：**默认 `DRAFT`（草稿）**——不要擅自改成 `PUBLISHED`；如需定时上线用 `SCHEDULED` + `publishAt`
- `zh` / `en`：**两份都写**（本站是双语站，只有中文会显得格格不入）
- `coverImagePath`：封面图的本地文件路径，工具自动上传
- 更新已有文章：传 `id`，**只传要改的字段**（其余保留原值）

**回执要读**——三种提示都很重要：

- 「自动补齐」：摘要自动生成，检查是否贴切
- 「格式提醒」：有 `#` 或内联样式被处理了，下次避免
- 「下一步」：草稿需人工发布

**推送后必须做的**：把工具返回的**后台编辑链接**（或预览链接）转给用户，让他过目后决定发布——这是流程的护栏，不要跳过。
